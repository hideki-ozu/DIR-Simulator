## 1. 性能・正しさ・再現性

| 項目 | 合格基準・測定方法 | 根拠・適用範囲 |
| --- | --- | --- |
| 小規模 | 単一バスと3コントローラ、500000 bit/s、各キュー容量2。CAN詳細仕様のCRC・ビット長の独立期待値、非競合、同時競合、転送中後着、飽和を検証する | DIR-TBD-0008、DIR-REQ-0116、DIR-AC-0009・DIR-AC-0025 |
| 計測精度 | 整数時刻・順序・件数・CRC・ビット長は期待値との完全一致。理論的な転送時間をceilする各区間の誤差は0以上1 ps未満。派生比率は絶対誤差1e-12以下または相対誤差1e-9以下 | 同じ量についてどちらかを満たす。区間ごとの丸め後の和は整数で完全一致を確認 |
| 中規模 | 単一バス、32コントローラ、500000 bit/s、8 byteデータ、ID 0x100から0x11F、データは全0、標準形式。各送信元31250件の周期要求で合計1000000件。キュー容量64、処理・経路遅延0 | 性能測定条件でありエンジンの最大対応規模とは区別 |
| 負荷の定義 | 各送信元iのフレーム＋3bit間隔の理論占有時間をC_i psとする。P=ceil(sum(C_i)/rho)、位相floor(i*P/32)、開始を位相、周期P、終了T=31250*Pとし、[0,T)に各31250件を生成する | rhoは通常0.30、高負荷0.90、過負荷1.20の3条件。初期フレーム内容から各C_iをCAN仕様のCRC・stuffingで独立計算 |
| 実行性能目標 | 3条件それぞれ、1000000件の要求を最後の出力確定まで120秒以内、プロセス最大常駐メモリ2 GiB以下 | releaseビルド、ストリームCSVと集計JSONを含む標準出力設定。各1回のウォームアップ後3回測定し、時間は中央値、メモリは3回の最大値で判定。未測定 |
| 基準機 | Ubuntu 24.04 x86_64、物理4コア以上、定格3.0GHz以上、RAM16GiB以上、ローカルSSD。実行はシミュレーション処理1スレッド、同時の評価実行数1、rustc1.85.0 | CPU型名・OS・依存lock・バイナリhash・実行時刻を結果に記録。違う基準機での比較は測定環境を併記して別系列にする |
| 測定量 | 準備から出力確定までのwall秒、イベント処理だけのwall秒、処理イベント数、要求数、最大RSS、出力byte数、バス使用率、待ちと破棄数 | wallとRSSは実行性能の比較に使用。注：仮想時刻のイベント順への入力は対象外 |
| 再現性 | 同じバイナリ・入力・registry・初期条件で3回実行し、結果仕様の決定的なイベント・集計部分を完全一致で比較する | run_id、wall時刻、wall性能、絶対入力パス等の環境情報は比較対象から分離 |
| 異環境 | 固定した実装・依存版でUbuntu 24.04のnative環境とWSL2上同環境を比較し、整数時刻・順序・件数の一致と派生比率の許容差を確認する | 他OS・別architectureは拡張時に同じ適合ケースを実行してサポート集合へ追加 |
| 判定の記録 | 測定入力・ハッシュ・全反復結果・基準・合否・差分を検証記録へ保存する。CAN/GWの取得済み製品試験は各検証仕様の実行記録へ対応付ける。中規模性能・全AC適合の判定は未完了 | 数値目標の変更は文書版と変更理由を残す |

## 2. 出自・依存関係・配布

| 項目 | 確定する運用 |
| --- | --- |
| プロジェクト | MIT OR Apache-2.0を維持。配布物へ両ライセンス本文を同梱する |
| 採用物台帳 | `docs/third-party/採用物台帳.md`を採用物追加時に作成し、一行一採用物で名前、版、用途、取得URL、取得日、ソースhash、SPDX式、著作者表示、改変有無、同梱文書、確認者、確認日、判定を記録する |
| 依存版 | Cargo.lockを配布ソースへ同梱し、直接・推移依存とも台帳と配布時の一覧に対応付ける。採用物がない時点は台帳に0件と記録できる |
| 公開仕様 | 参照規格・公開仕様の版、URL、使用した節と実装責務の対応を記録し、仕様からの独立実装としてコードレビューする。注：OMNeT++・INETの実装コード流用は既定の独立実装方針の対象外 |
| 採用判断 | 出自と適用ライセンスを確認した採用物を追加する。判定は採用可、条件付き採用可、要確認のいずれか。要確認は取得と評価用に記録し、配布集合は条件を充足した採用物で構成する |
| 配布確認 | 版固定、hash、必要な著作者表示・NOTICE・ライセンス本文・改変表示の充足をレビューし、配布集合の台帳版をresults.metadata.adoption_ledger_versionへ記録し、manifest.metadata_refから参照。ライセンスの意味の自動判定は確認者の判断の補助に限定 |
| SPDX | 識別子・式はSPDXの表記を採用し、個別条件は採用元の本文と照合する。台帳の標準識別子は利用条件そのものの確認を置き換えるものではない |
| 検証 | DIR-TBD-0010、DIR-REQ-0048・DIR-REQ-0049、DIR-AC-0008。[DIR-TEST-0085～0087](verification/cases/利用フロー・品質検証仕様書.md#dir-test-0085)でRust実装・NED独立実装・出自のレビュー手順と合格条件を規定し、実装・採用物の追加時に結果を記録。現時点で全依存物の適合を確認済みとする意味ではない |
