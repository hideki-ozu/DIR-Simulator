## 正本と公開先

`docs/guide/*.md`が標準Markdown正本です。ナビ・検索・Unicode見出しアンカーは`mkdocs.yml`、実行入力は`examples/guide/can`と`examples/guide/canfd`、スクリーンショットは`docs/guide/assets`で管理します。navは29ページ（27記事＋入口・ライセンス表示の2ページ）です。実ブラウザも404を除く29ページを巡回し、生成HTMLは404込み30件です。執筆者向けの本書と`docs/Qiita移植メモ.md`は公開対象`docs/guide`の外で管理します。

公開先は`https://hideki-ozu.github.io/DIR-Simulator/`です。`site_url`にリポジトリのサブパスを含め、ページ・画像・検索workerは相対URLで解決します。GitHub Pagesへ配信するのは`build/guide`だけです。`guide-evidence`、開発用依存、元の作業領域は公開しません。

`build`と`guide-evidence`はGit管理から除外します。HTMLを手編集せず、正本から生成します。検証レポートは`docs/verification/results/guide-local-verification.json`、生成元は`scripts/record_guide_verification.py`です。

## PRから公開まで

`.github/workflows/guide-pages.yml`は次の流れです。

1. main宛てのPRでPython 3.11とMkDocs 1.6.1を準備します。
2. 実習ZIPとGit管理中の入力が一致するか検査します。
3. `mkdocs build --strict`、ローカルリンク・アンカー・画像・公開資産検査を行います。
4. PRでは公開しません。変更内容とCI結果を確認して、利用者がマージを判断します。
5. mainへのpush（PRマージを含む）でも同じ検証を実行します。成功後だけPages artifactを作り、`github-pages`環境へ配信します。

PRのApproveだけでは公開しません。個別PRのマージと自動マージ設定はこのworkflowに含めません。検証が失敗すれば公開ジョブは進まず、既存公開版を維持します。

ビルドジョブは`contents: read`のみです。公開ジョブだけが`pages: write`と`id-token: write`を持ちます。checkoutは資格情報を残さず、公式checkout/setup-python/configure-pages/upload-pages-artifact/deploy-pagesを確認済みSHAで固定します。追加のsecretや外部エージェントは不要です。

初回はリポジトリのSettings → Pages → Build and deploymentでSourceをGitHub Actionsに設定します。Pages APIの`build_type: workflow`でも同じ設定を行えます。これは公開経路の初期設定で、実際のガイド配信はmainへマージした後のworkflowで行います。公開ジョブの環境保護により追加承認が表示された場合は、その設定に従います。

公式資料：

- [GitHub Pagesのcustom workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
- [Pages設定API](https://docs.github.com/en/rest/pages/pages#create-a-github-pages-site)
- [deploy-pages](https://github.com/actions/deploy-pages)

## ローカルビルド

リポジトリルートから実行します。依存はプロジェクト専用環境へ配置します。

```bash
python -m venv .venv-guide
source .venv-guide/bin/activate
# Windows PowerShell: .venv-guide/Scripts/Activate.ps1
python -m pip install -r requirements-guide.txt
python scripts/build_guide_inputs.py --check
python -m mkdocs build --strict
python scripts/check_guide_links.py
```

GitHub Pagesと同じ`/DIR-Simulator/`をローカルで確認する場合は、生成した`build/guide`を一時配信用ディレクトリの`DIR-Simulator`へコピーし、その親をHTTP配信します。`scripts/verify_guide_browser.cjs`は自動でリポジトリサブパスのローカルHTTPサーバーを起動します。

検索は`lang: [ja]`、`min_search_length: 2`です。英語も含む日本語tokenizerを使います。`en`を追加すると英語のstopword `can`がCAN検索を落とすため追加しません。Unicode slugを使い、見出しを数字から始めない構成で既定テーマの目次選択エラーを避けています。

