## 1. 目的

CAN／CAN FD、Ethernet、GW・Switch、SoCバス／AXI／AHB／NoC、DDR／SRAM、共有メモリIPC／DMA／メールボックスIPCの通信と共有資源を離散イベントシミュレーションで評価し、送信条件・ビットレート・バッファ容量の違いによる遅延、競合、使用量、性能の変化を比較できるようにする。
本書は必要な能力・観測可能な結果・受け入れ条件を管理する。構文、状態遷移、出力スキーマの確定内容は[機能仕様書](機能仕様書.md)、内部構造・アルゴリズム・Rust API案は[アーキテクチャ設計書](アーキテクチャ設計書.md)で具体化する。

### 1.3. 要件階層の読み方と管理元

本書は、対象と提供段階を確認した後に、共通基盤、基準CAN、将来モデル、横断品質の順で読む構成とする。要件番号は識別子であり、読順や重要度を表さない。各要件表では上位の能力を先に示し、その下に実現する責務と確認条件をまとめる。

| 読む順序 | 確認する内容 | 本文の入口 |
| --- | --- | --- |
| 対象と提供段階 | 0.1.0のClassical CANと将来対応予定の区別 | 第2章、[CAN評価](#dir-req-0001) |
| 共通基盤の準備 | 構造、実験条件、準備失敗の診断 | 第3.1～3.3節、[構造定義](#dir-req-0005) |
| 共通基盤の実行・観測 | イベント、資源、終了、時系列・集計 | 第3.4～3.5節、[実行](#dir-req-0007)、[結果取得](#dir-req-0008) |
| 基準モデル | CANの構成・負荷から仲裁・転送・受信・評価まで | 第3.6節、[CAN通信](#dir-req-0058) |
| 拡張の共通契約 | 登録契約の維持と追加profileの選択・入力・結果 | 第3.7節、[拡張契約](#dir-req-0122)、[追加モデル選択](#dir-req-0157) |
| 将来モデルの固有責務 | GW、CAN FD、Ethernet、SoC内部通信、メモリ・IPC | 第3.8～3.12節。各モデルの上位要件から子要件へ進む |
| 全体に適用する条件 | 再現性、利用手順、実装・互換性、受け入れと決定記録 | 第4～7章 |

要件の条件・期待結果・検証先は本書、各有効要件の主親・階層上の位置・分解状態は[要件階層.json](要件階層.json)を正本とする。[別紙：要件階層（HTML）](要件階層.html)は両者から生成する。JSONの配列順は本書の要件掲載順に揃え、親を子より先に記載する。

見出しは読みやすさのための責務分類であり、それ自体は要件や主親を追加しない。「上位」は子を持つ根、「中位」は親と子を持つ要件、「末端」は子を持たない要件を表す。木の深さを三段へ制限するものではなく、末端であることも実装・検証完了を意味しない。複数の責務に適用する要件は本文を複製せず参照する。特に再現性・診断・計測の意味付け・拡張時の契約維持は、主親だけから適用範囲を判断しない。

### 2.2. 利用フロー

構造を定義し、実験条件を確定してから実行し、観測結果を比較する。上位要件の本文は第3章の各責務の先頭に置き、同じ節で子要件へ読み進められるようにする。

| 順序 | 上位要件 | 次の工程へ渡すもの |
| --- | --- | --- |
| 1. 構造を定義する | [DIR-REQ-0005](#dir-req-0005) | 型・インスタンス・接続・デフォルト値 |
| 2. 実験条件を確定する | [DIR-REQ-0006](#dir-req-0006) | 検証済みのパラメータと初期化したモデル |
| 3. 仮想時刻に沿って実行する | [DIR-REQ-0007](#dir-req-0007) | 通信・資源の状態変化、終了状態、確定済みの観測 |
| 4. 結果を取得・比較する | [DIR-REQ-0008](#dir-req-0008) | 条件と対応付いた時系列・集計・診断 |

入力検証は各準備工程に、再現性と異常終了の扱いは実行全体に適用する。モデル固有の仲裁・転送・応答は共通実行の中で動作し、別の実行基盤を構成するものではない。
