## 1. INIとパスの契約

[INI読み込み](../機能仕様書.md#dir-func-0007)と[値解決](../機能仕様書.md#dir-func-0008)を具体化する。構造入力は[NED詳細機能仕様書](NED詳細機能仕様書.md#syntax)を正とする。

[実験条件の初期化の親要件](../要件定義書.md#dir-req-0006)のうち、本書は実行条件の選択とインスタンス別確定値の作成を担当する。入力はINI、NEDの展開構造・宣言型・default、登録スキーマである。出力は実行時間・上限・観測窓と、各インスタンス／channelの型・物理量・正規化値・採用元・元位置であり、[生成・初期化](診断詳細機能仕様書.md#lifecycle)へ渡す。[生成と初期化の要件](../要件定義書.md#dir-req-0030)はこの出力を使う後段の責務である。

同型の二インスタンスで一方だけを上書きする確認は、[INIの優先](../要件定義書.md#dir-req-0025)と[基準値の保持](../要件定義書.md#dir-req-0026)を共同で確認する。さらに宣言型・単位・値域に適合した値がそれぞれの初期状態へ渡るまでが親要件の確認範囲となる。構文や値解決の合格と、モデルの初期化成功は別の段階として記録する。

<a id="ini"></a>

```trace
{
  "id": "spec-configuration#ini",
  "stage": "spec",
  "requirements": [
    "DIR-REQ-0006",
    "DIR-REQ-0024",
    "DIR-REQ-0057"
  ],
  "upstream": [
    "DIR-FUNC-0007",
    "DIR-FUNC-0008",
    "DIR-FUNC-0021"
  ],
  "state": "confirmed",
  "pending": []
}
```

| 項目 | 型・必須性・規則 | 受理／拒否例 |
| --- | --- | --- |
| 文法 | UTF-8、任意先頭BOM、LF/CRLF。一行一代入 `key = value`、前後空白無視、空行と行頭 `#` または `;` コメントを受理。注：行末コメントは採用範囲外。節前のキー、複数行値、include、環境変数展開、式、ワイルドカード、継承は拒否。キー・節・パスは大文字小文字を区別 | `network = demo.Main` は受理、`**.bitrate=1Mbps` は拒否 |
| 節 | `[General]` を一回必須とし、その後に任意個の `[Channel 接続識別]` を許可。General以外の設定プロファイル節は拒否。Generalの実行キーとインスタンス別キーを混在可能。Channel節の同一識別の再登場は拒否 | `[Config Fast]` は拒否 |
| network | 必須、完全修飾型名トークン。空値不可。型のnetwork種別を検査する。起点インスタンス名は型の末尾名 | `network = demo.Main` → `Main` |
| ned-path | 必須、一個以上の二重引用文字列を `;` で区切ったリスト。空要素は拒否。末尾区切りなし。文法は `String { ";" String }` で、トークン間のSP/TABを受理する。引用内のセミコロンは区切りでなくパスの一部。指定順を保持 | `ned-path = "models";"vendor-models"` は受理 |
| sim-time-limit | 必須、単位付き時間。0以上u64最大psまで。丸めのない整数ps換算が必要。通常終了の観測終端はイベント枯渇時でもこの値 | `0ps` と `1ms` は受理、単位なし `1` は拒否 |
| metrics-window | 任意、正の単位付き時間、既定値 `1ms`。整数ps換算で1以上u64最大まで。集計窓の意味は結果仕様を正とする | `1ms` は受理、`0ps` は値域エラー |
| max-events | 任意、単位なし十進正整数、既定値 `100000000`、範囲1～u64最大。実行イベント数の上限としてイベント仕様へ渡す | `100000000` は受理、`0` は値域エラー |
| max-delta-cycles | 任意、単位なし十進正整数、既定値 `1000000`、範囲1～u64最大。同時刻デルタサイクル上限としてイベント仕様へ渡す | `1000000` は受理、負値・小数は型／値域エラー |
| model-profile / model-config | [拡張モデル共通仕様](拡張モデル共通詳細機能仕様書.md#selection)の選択・構成キー。model-profile既定can.cc.ideal.v1、model-configは追加profile必須 | 引用文字列として解釈 |
| workload | 任意、一個の二重引用パス文字列。省略時は空の生成器集合。指定時はファイル必須。JSONの入力項目・形式は選択profileに従う。既定CANは[CANモデル詳細仕様](models/CANモデル詳細機能仕様書.md#workload)、追加profileは[拡張共通仕様](拡張モデル共通詳細機能仕様書.md#inputs)を適用 | `workload = "workload.json"` は受理、空文字は拒否 |
| 相対パス | configはCLI起動cwd基準。ned-path・workload・model-configはconfigファイルの親ディレクトリ基準。絶対パスも受理。パス内の `.`、`..` は正規化。正規化後の同じルートや包含ルートはNED規則で拒否。config/workload/model-configのシンボリックリンクは拒否、通常ファイルのみ。入力は実行前に一度読み切り、そのスナップショットを実行終了まで使用する | cwd変更時も同じ絶対configなら同じ入力を選択 |
| パラメータキー | General内で `Root.child.parameter = リテラル`。階層の完全パスを要求し、root自身にも指定可。最終区切りより前をインスタンス、末尾をパラメータとして解決。未知インスタンス／パラメータは拒否 | `Main.a.queueCapacity = 32` |
| channel設定 | `[Channel Main::a.tx]` 内の `delay = 2ns` のように宣言パラメータ名で指定。識別はNED仕様の親パス＋始点。channelなしの辺への設定は拒否。注：暗黙channel生成、型の変更、インスタンス命名は採用範囲外 | 同型Wireの別辺の値は変わらない |
| 行とトークン | 行末はLFまたはCRLF、最終行の改行は任意。前後空白はASCII SP/TABのみ。先頭のSP/TABを除いた最初の文字が `#` または `;` の行をコメントとする。代入は最初の引用符外 `=` を境界とし、その左右をキーと値として完全消費する。引用文字列中の `=;#` は通常の文字。空値は入力失敗とする。注：単独CRと行末コメントは入力文法に含めない | `rxFilter = "*" # x` は拒否 |
| キーと節の字句 | Generalの実行キーは本表の完全一致。それ以外は `InstancePath "." ID`。ChannelのキーはIDのみ。INIの完全名・パス・端点はNEDの識別子規則を用い、内部空白なし。節は `[General]` または `[Channel `＋接続識別＋`]` で、Channel直後は一個のASCII SP。接続識別は `InstancePath "::" Endpoint`。節行は外側SP/TABだけを許可する | `[ General ]`、`[Channel  Main::a.tx]` は拒否 |
| 文字列とパス | パスも第2節のstringリテラルを使い、一度だけエスケープ解釈してからファイルシステムへ渡す。パス区切りは `/`、大小文字を保持しUnicode正規化を行わない。空文字および解釈後にU+0000～U+001F/U+007Fを含むパスは入力失敗。拡張子はconfig/workloadでは任意 | `"models/a"` は受理 |
| 重複・未知 | 同一節の同一キーは値が同じでも重複として拒否。未知Generalキー、未知節、重複節、CLIと同義のINI出力キーも拒否。全入力検証後に初期化へ進む | 二つの `Main.a.queueCapacity` は重複として失敗 |

## 2. 値の優先・型・単位

[型検証と換算](../機能仕様書.md#dir-func-0009)は入力の十進数を正確に解釈する。

<a id="values"></a>

```trace
{
  "id": "spec-configuration#values",
  "stage": "spec",
  "requirements": [
    "DIR-REQ-0018",
    "DIR-REQ-0024",
    "DIR-REQ-0025",
    "DIR-REQ-0026",
    "DIR-REQ-0027",
    "DIR-REQ-0052",
    "DIR-REQ-0119",
    "DIR-REQ-0057",
    "DIR-REQ-0006"
  ],
  "upstream": [
    "DIR-FUNC-0008",
    "DIR-FUNC-0009"
  ],
  "state": "confirmed",
  "pending": []
}
```

| 項目 | 確定規則 | 正常／境界／異常 |
| --- | --- | --- |
| 優先順位 | NED宣言型を検証した後、INIの同一対象への一つの有効な指定を優先し、なければNEDのdefault値を使用する。両方なければ必須値欠落。INIで隠されたdefault値も型・単位・値域を検証する。simple/channelのスキーマは宣言の全パラメータを要求し、宣言漏れを入力失敗として診断する | a.queueCapacity=32ならaだけ32、bは64 |
| int | 符号省略可または `-`＋十進整数。無単位はi64の範囲。先頭 `+`、指数、16進、桁区切り、浮動小数表記を拒否。0以外の先頭ゼロは拒否。`-0` は整数0として保持する。単位付きintは整数字句の量を正確換算し、換算後の量をu64で保持する（物理量の正規化型による例外）。時間・速度・データ量の各行の非負条件とu64範囲を適用する | `64` 受理、`64.0`、`0x40` 拒否 |
| double | 符号付き十進数 `-?[0-9]+(\.[0-9]+)?` の字句（`.` は小数点）。指数、NaN、Infinity、符号付きゼロ、先頭ゼロ付き整数部は拒否。無単位は有限binary64に最も近い値へties-to-evenで一回変換し、非零が0になるアンダーフローと無限大へのオーバーフローを拒否。量付きは次行の正確換算を優先 | `0.5` 受理、`.5`、`1e3`、`NaN` 拒否 |
| bool | 小文字 `true`、`false` のみ | `1`、`TRUE` は拒否 |
| string | 二重引用のUTF-8文字列。`\"`、`\\`、`\n`、`\r`、`\t` のみエスケープとして受理。生の改行、U+0000～U+001FとU+007Fの制御文字、不正エスケープを拒否。外側引用を除いて値を保持。引用省略はnetworkのように専用文法を持つ実行キーに限定 | `"*"` 受理、引用なし `*` はstringとして拒否 |
| リテラルの完全消費 | 数値の符号・整数部・小数部は連続した一トークン。数値と単位の間にはNEDでは空白またはコメント、INIではSP/TABだけを許可する。字句の整数部は `0` または `[1-9][0-9]*`。intの小数部は常に省略、doubleの小数部は任意で少なくとも一桁。doubleでは正の `0` と `0.0` を受理し、負符号付きの数値ゼロは全て入力失敗。前後の区切りを除いて文字が残る値は入力失敗とする | `1 ms` は受理、`1 0ms` は拒否 |
| 実行数値キーの字句 | sim-time-limitとmetrics-windowは単位付きdoubleの十進字句と時間換算を用いる。max-events/max-delta-cyclesは符号なしの `0` または `[1-9][0-9]*` をu64へ直接変換し、その後に正数条件を検査する。実行キーはNED intのi64上限から独立する | `max-events = 18446744073709551615` は受理 |
| unit契約 | 数値宣言の `@unit(s)` は時間、`@unit(bps)` は速度、`@unit(B)` はデータ量。unit属性がある値には対応量の単位を必須とし、属性がない数値への単位付加を拒否。単位は大小文字区別、数値と単位の間の空白は任意、複合式は拒否 | 時間へ `500kbps` は物理量エラー |
| 時間単位 | `ps`=1、`ns`=1000、`us`=10^6、`ms`=10^9、`s`=10^12 ps。十進有理数として掛け、結果が0以上の整数u64であることを要求。量付き数値は宣言型を別途保持したうえで整数の正規化値として保持する | `0.001ns`=1ps、`0.1ps` は精度不足、`18446744073709551615ps` は表現上限、これより1ps大きいと桁あふれ |
| 速度単位 | `bps`、`kbps`、`Mbps`、`Gbps` の係数1、10^3、10^6、10^9。換算結果は0以上整数u64 bps。モデルの速度条件を追加適用する | `0.5Mbps`=`500kbps`=500000bps、`0.5bps` 拒否 |
| データ量単位 | `B`、`kB`、`MB`、`GB` の係数1、10^3、10^6、10^9、`KiB`、`MiB`、`GiB` の係数2^10、2^20、2^30。換算結果は0以上整数u64 byte。`b`やbit単位は未採用 | `1KiB`=1024B、`0.5B` 拒否 |
| 値域の追加 | 一般リテラルの表現範囲とモデルの意味上の範囲を両方検査する。queueCapacity、bitrate、処理遅延、filter等のモデル固有範囲は選択profileのモデル仕様を正とする。既定CANは[CAN仕様](models/CANモデル詳細機能仕様書.md#controller)を適用。途中換算も任意精度整数／十進計算で検証し、換算失敗を入力エラーとして返す | intとして負の容量を読めてもモデル値域で拒否 |
| 確定値の保持 | 全インスタンス・channelごとに宣言型、物理量、正規化値、採用元（INIまたはNED default）、元ファイル行列を保存する。採用元は値トークン位置、宣言位置も別途保持し、上書き後もdefaultの検証位置を失わない。時間・速度・データ量のu64をJSONへ出す場合は十進文字列と明示的単位を用いる | 2nsの時間値は `"2000"`、単位 `ps` |

| 条件 | 結果・確認方法 |
| --- | --- |
| 位置と検証順 | [診断仕様](診断詳細機能仕様書.md#diagnostic-schema)の文字位置と[準備順序](診断詳細機能仕様書.md#lifecycle)を適用する。未知キーはキー、型・単位・値域は値のトークン全体、重複は二回目のキー／節を原因位置とし最初の位置を関連位置へ記録する。実行必須キーの欠落はGeneral節、パラメータ必須値の欠落はNED宣言位置へ関連付ける |
| 入力失敗 | ファイル取得、字句・構文、未知参照、未対応書式、重複、型・単位、値域、欠落を `E-0001` の準備失敗として返す。原因、対象パス／キー、入力ファイル、判明する開始行列（1起点）を含める。元位置が存在しない欠落は宣言位置、読取不能はファイルを示す。イベント処理へ移る前に準備失敗として終了する。共通診断の出力形式・終了コードは診断・インタフェース詳細仕様を正とする |
| 最小正常入力 | [NED仕様の完全入力](NED詳細機能仕様書.md#examples)を用いる。sim-time-limit=1ms→1000000000ps、bitrate=500kbps→500000bps、queueCapacityの省略→64。workload省略は有効であり、存在しないworkloadを指定した場合とは区別 |
| 上書き正常 | Generalに `Main.a.queueCapacity = 32` を追記。a=32、b=64。Channel Main::a.txにdelay=2nsを指定するとその辺だけ2000ps。各採用元をINIとして保持 |
| 必須欠落 | Main.bus.bitrateのINI行を削除：NEDにdefaultがないため必須値欠落。sim-time-limitを削除：Generalの必須キー欠落 |
| 型・精度異常 | `Main.a.queueCapacity = "32"` は型不整合。`sim-time-limit = -1ps` は負値、`0.1ps` は非整数換算、`1Mbps` は物理量不整合。いずれも元の入力値を含む準備失敗として診断する |
| 範囲端点 | sim-time-limit=0psは受理し時刻0の実行方針はイベント仕様に従う。u64最大psは表現として受理し、それを超える入力は拒否。実行中の時刻加算はイベント仕様で別途検査 |
| 追加実装 | 新しいNED型名と `@class` キー・スキーマを登録することで、同じGeneral／Channelキー解決を再利用する。将来の複数バスでもRoot以下の完全パス、辺識別、値型は変えない。新しい単位・節・ワイルドカードは別仕様版で明示追加する |
| 確認状態 | [DIR-AC-0002](../要件定義書.md#dir-ac-0002)、[DIR-AC-0013](../要件定義書.md#dir-ac-0013)、[DIR-AC-0014](../要件定義書.md#dir-ac-0014)の具体期待値として扱う。規則と[入力・設定詳細設計](../design/入力・設定詳細設計書.md)・[検証ケース](../verification/cases/入力・設定検証仕様書.md)を規定済み。実装・製品試験は未実施 |

## 拡張モデルの設定分担

| 分野 | 採用規則 |
| --- | --- |
| 共通INI | 構文・単位・同じ完全パスへの上書き・重複キー診断を全profileで共用する |
| profileキー | model-profileとmodel-configは[拡張共通仕様](拡張モデル共通詳細機能仕様書.md#inputs)を正とする。新しい記法をINIへ増やす代わりに、モデル固有の表・配列は版付きJSONへ置く |
| モデルの構成 | GW経路表、AXIのアドレス／READY、Ethernet FDBは各モデルJSONの必須項目・値域を検証する。未知項目は当該profileの準備診断 |
| 負荷 | 既定CANのschema1を維持し、追加モデルは共通schema2のgenerator decoderから個別kindを解決する |

| 項目 | 契約 |
| --- | --- |
| Ethernet v2 | model-profileは`"ethernet.l2.store-forward.v2"`。model-configへ媒体別PHY・duplex・固定PHY遅延・backoff seedを追加する。選択可能な組合せ・必須値・正規化は[媒体仕様](models/Ethernet媒体拡張詳細機能仕様書.md)を正とする |

## 将来対応モデルへの適用

現行0.1.0はClassical CANを対象とし、以下は将来モデルを同じ値解決へ接続する契約である。profileの選択肢と提供時期は[拡張共通仕様](拡張モデル共通詳細機能仕様書.md#selection)を参照する。

| 項目 | 契約 |
