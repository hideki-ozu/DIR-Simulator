5. EventKeyの時刻/delta/phase/sequenceを照合し、phase0→phase1の固定点→資源ID順phase2と次deltaを確認する。結果だけ同じでも順序違反は不合格。

## 5. 小規模の正しさと中規模性能

[品質方針第1節](../../品質・配布方針.md)を入力と参考計測手順の正本とする。DIR-AC-0009・0025では、測定手順と記録を確認し、wall・RSSの数値目標を必須の合否から外す。次の反復手順は比較用に推奨し、未測定を不合格にしない。件数保存・決定性・出力整合の合否は別に記録する。

1. 先にCAN DIR-TEST-0001～0006を合格させる。小規模の整数値・CRC・仲裁・件数保存と派生量の許容差を確認し、性能測定で意味が変わっていないことの基準にする。
2. 規定の32送信元、各31250件、8byte全0、標準ID0x100..0x11Fから独立serializerでC_iを求め、rho=0.30/0.90/1.20ごとにP、位相、Tを生成する。浮動小数点rhoで入力時刻を丸めず3/10,9/10,6/5の有理数を使う。各送信元の時刻列が[0,T)に31250件、合計1000000件であることを実行前に確認する。
3. 入力一式とhash、生成式、C_i、binary・依存lock・環境・出力設定を保存する。基準機条件を満たすrelease、実行1スレッド・同時評価1件で各条件ウォームアップ1回、計測3回を行う。
4. 測定開始はCLIプロセス起動による準備開始、終了はmanifest確定とプロセス終了。外部計測器でwallと最大RSSを記録し、内部のイベント処理wallと混同しない。途中失敗・観測上限による中断は未完走の参考計測として記録し、短い時間を完了性能にしない。機能不具合による失敗は正しさの判定で扱う。
5. 各条件で総wallの中央値と最大RSSの3回最大値を報告し、120秒・2147483648byteとの参考差を記録する。wall・RSSの超過は受け入れ・PR・公開の不合格条件にしない。全反復値、event数、要求数、出力byte数、使用率、待ち、破棄、未完了を記録する。過負荷でも1000000生成の保存則が成立し、Tで未完了が残る場合を脱落扱いにしない。
6. 同条件の決定的な結果を3回比較する。通常／高負荷／過負荷の各結果を同じ指標定義で比較し、実測なしに単調性やゼロ破棄を仮定しない。異なる機械の値は別系列として報告する。

記録表の列はcondition/input_hash/binary_hash/environment/repetition/wall_total/wall_events/max_rss/events/generated/output_bytes/termination/correctness/reference_performance（必須合否なし）。[2026-10-06のWSL2実測](../results/can-million-performance-2026-10-06.json)に入力・バイナリhash、全反復値、保護上限と中断結果を保存した。3負荷条件で2 GiBのメモリ目標を超過し、出力確定まで完了しなかった。メモリ保護または180秒の観測上限による中断の時間は完了時間ではなく、観測RSSは無制限実行の最大値とは別である。イベント処理のみの時間と、完成した製品出力を要する件数・使用率・待ち・破棄・再現性は未取得として記録する。native基準機の参考測定は未実施。取得時の旧判定は保存記録のまま保持する。期待値checkerの所要時間を本ケースの製品性能実績として使用しない。

同日の[逐次処理改修後の記録](../results/can-streaming-2026-10-06.json)は、3,200要求の3条件の各1回完了と、100万要求通常負荷の各1回観測を別系列として保存する。100万要求の観測最大RSSは115.098 MiBで、120秒後も未完了、180秒上限で停止した。反復計測の代表値、完成出力の再現性、無制限実行の最大RSSをこの1回観測から推定しない。現在はwall・RSSに必須の合格閾値を設けない。内部タイマーは実装し完了した小規模条件で値を取得したが、強制停止した100万要求ではCLI最終報告がなく未取得である。

[2026-10-08の出力最適化統合後の完走記録](../results/can-million-integrated-2026-10-08.md)は、①〜⑤を適用した版で各条件1回の完走観測を行った別系列である。通常／高負荷／過負荷のwallは754.75／740.48／592.35秒、全プロセス最大RSSは47.41／49.06／47.88 MiBだった。取得時は時間がすべて旧参考値120秒を超え、反復へ進めなかった。全条件で終了コード0、manifestの4ファイル照合、生成件数1000000を確認し、過負荷は成功833375・破棄166241・未完了384の保存則を確認した。今回初めて完走時のRSSと内部イベント処理wallを取得したが、上記手順の3測定中央値・3測定最大RSS・同条件の反復再現性とは区別する。native基準機の参考測定は未実施である。wall・RSSの必須合否は現在の方針で廃止し、取得時の記録を保持する。
