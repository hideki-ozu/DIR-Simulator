## 1. 対象・入力・共通判定

[入力・設定設計](../../design/入力・設定詳細設計書.md)の内部表と、[NED](../../specs/NED詳細機能仕様書.md)、[設定](../../specs/設定詳細機能仕様書.md)、[診断](../../specs/診断詳細機能仕様書.md)の外部動作を照合する。対象はDIR-FUNC-0002～0010/0021の入力・登録責務、[DIR-AC-0001](../../要件定義書.md#dir-ac-0001)/[0002](../../要件定義書.md#dir-ac-0002)/[0008](../../要件定義書.md#dir-ac-0008)/[0010](../../要件定義書.md#dir-ac-0010)/[0013](../../要件定義書.md#dir-ac-0013)/[0014](../../要件定義書.md#dir-ac-0014)である。物理CAN時間や出力schemaは各既存検証で独立に判定する。

各表の行は独立したサブケースとし、次の基底を新しい一時ディレクトリ`/work/input-case`へ複製して指定箇所だけ変更する。BOMなしUTF-8/LF、末尾改行あり、Registryは組込みCAN/FixedDelay登録集合、workload省略、出力先は未使用とする。製品試験では`dir-simulator run --config /work/input-case/scenario.ini --output /work/input-case/results`を実行する。内部段階試験では製品の同じloader/resolverへ渡し、停止段階と未実行段階を記録する。内部試験用のRegistryと観測hookを製品の新profileとして提供することは要求しない。

`models/demo/Main.ned`の全文：

```ned
package demo;
simple Controller {
    parameters:
        @class("dir.can.Controller");
        int queueCapacity = default(64);
        double txProcessingDelay @unit(s) = default(0ps);
        double rxProcessingDelay @unit(s) = default(0ps);
        string rxFilter = default("*");
    gates:
        output tx;
        input rx;
}
simple Bus {
    parameters:
        @class("dir.can.Bus");
        double bitrate @unit(bps);
        string profile = default("can.cc.ideal.v1");
    gates:
        input rx_a;
        output tx_a;
        input rx_b;
        output tx_b;
}
channel Wire {
    parameters:
        @class("dir.link.FixedDelay");
        double delay @unit(s) = default(0ps);
}
network Main {
    submodules:
        a: demo.Controller;
        b: demo.Controller;
        bus: demo.Bus;
    connections:
        a.tx --> demo.Wire --> bus.rx_a;
        bus.tx_a --> demo.Wire --> a.rx;
        b.tx --> demo.Wire --> bus.rx_b;
        bus.tx_b --> demo.Wire --> b.rx;
}
```

`scenario.ini`の全文（以下の行位置の基準）：

```ini
[General]
network = demo.Main
ned-path = "models"
sim-time-limit = 1ms
Main.bus.bitrate = 500kbps
```
