実装済みcomponentの互換表をport/class/domain別に検証する。最低限の製品gateはfull-duplex named PHY+forwarding+clock+shapingと、shared named PHY+forwarding+複数実受信であり、双方の保存継続を比較する。未知adapter、二重physical/retry owner、時計domain不整合は具体的な入力位置で拒否する。

半二重carrier待ち、collision/retry、gate閉鎖とhold、CBSの解析credit、PAUSE/PFCのeffective構成、時計補正/GCL置換境界の実SOFとoverrun、再hashしたowner/wake/time改変を確認する。非標準な実験policyを実装する場合はexplicit experimental名で選択し、IEEE支持範囲に含めない。

shared named PHY、raw Qcc、PAUSE/configured-mediaと、WireHostの実serializerへの接続を個別の製品gateで確認している。一般的なadapter graphと全互換組合せの最終判定は継続中である。

PAUSE/configured-mediaは`network_pause_media`で実生成・受信、zero/短縮/最大quantaへの置換、同期MAC完了待ち、旧timerの継続、同時刻のexpiryと再要求、admin/link epoch、closed GCLとnegative CBS、half-duplex collision/defer/retryを確認する。通常protocol FIFOの先頭がgateで待機中でもtyped MAC Controlが送信できることを確認する。数値PHYのtimerは宣言link bitrateに置き換えず、実symbol rate/2の独立期待値と比較する。

`docs/verification/fixtures/mac-control/verify_result.py`は製品codecをimportせず、実64byte frameのreserved DA、opcode、padding、zlib CRC、TXとRXのidentity、受信要求と物理rate timerの対応を照合する。CBSのcreditは別の解析積分oracleで確認する。このbyte oracleだけでCBS又は規格全体の適合を判定しない。

保存継続はPAUSEのpending/active/expiryとretained retry、実sampled controlの受信待ちを含む複数cutから別プロセスで比較する。codec19の選択、再hashした状態改変の拒否、失敗時のowner/FES/journalの原子性を確認する。Viewerは現在cutまでのPAUSE状態を再構成し、configured-mediaの予定EOF/release/arrivalを実受信として表示しない。末尾からの巻き戻しでも未来のtimerを表示しない。

raw Qccは`network_qcc`の実startup後の予約・install・受信、実serializerで遅らせたLLDP/Verify/Respondのsliding-start上限、pending/installed双方で全packet排出後の実MDI lossによる保証取り消しを確認する。別プロセスの継続と、certificate/config/epoch/Pmax/source identityを再hashした5変種の拒否を独立に記録する。一般Wire producerの未証明到着上限を既知と仮定しない。

`network_wire_serializers`は既存WireHost FIFOからClause99及びproject抽象expressへの実送信・受信、pMAC中断と再開、同じclassに異なる長さの制御frameとdataがある場合の個別gate fitを確認する。制御frameのCRCとfragment境界は製品codecを呼ばないoracleで照合する。project PAUSE生成の明示policy、既存policyでの生成拒否、Clause99/half-duplexの標準上の拒否と別outputの受理を分けて検査する。

raw sample cutは整数通知時刻と物理referenceを分ける。1/3ps・2/3psの位相、非zero origin、期限後55psの要求とstale/future sampleの拒否、同じ通知cutで初めて到着した要求又は許可変更が過去の物理cutを使わないことを検査する。他portの継続通信で送信が永久に抑止されないことと、ABAの許可変更をsemantic epochで検出することを確認する。信用がちょうど回復した数学上の瞬間からの無条件8ns保証と、既知の整数回復cut以後のcut間隔を混同しない。

## Serializer resetと公開証跡の追加gate

`network_wire_serializers`でpreemptable送信中、suspended Data、EXPRESS、fragment/gap境界、EOF前後、遅延arrival、受信後IPG中、queued recovery、同時刻down/upと新しいclaim後の古いcallbackを扱う。fresh-process checkpointと予約失敗のatomic rollbackを製品経路で照合する。これらの最終gateの合否は実行記録に記載する。

公開GP証跡のsource数値IDは、実producerが出した`attempt_index`、Mergeの`transfer_index`、abstract decisionの`active_transfer_index`にも照合する。stable transfer ID、direction、epoch、物理endpoint、実SOF/予定EOF/arrivalの一致を併せて検査し、数値IDだけを変更したmutantを拒否する。private source replayと凍結入力prefixの照合は別の権限として維持する。

Viewerのreset回帰では、aborted fragmentを完了byte数に加えず、切断後にoccupationを増やさず、受信済み成功を保持する。切断前へ戻ると未来の`reset_ps`と部分送信量は現れない。
