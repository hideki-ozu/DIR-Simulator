## 1. 担当境界とデータの寿命

本書は[構造定義](../要件定義書.md#dir-req-0005)と[実験条件の初期化](../要件定義書.md#dir-req-0006)を、ファイルの取得から検証済みの生成入力まで具体化する。利用者への受理条件は以下の詳細仕様を正とし、内部型名は責務を説明する名称とする。公開Rust APIの別定義を作らず、実装後の宣言はソース・生成API文書へ対応付ける。

| データ | 所有者・寿命 | 不変条件 |
| --- | --- | --- |
| InputSnapshot / SourceFile | prepareが正規絶対パス、論理パス、取得bytes、復号テキスト、行開始表を所有。成功時は実行終了まで保持 | 各ファイルを一度読み切り、後段は再読込しない。bytesは結果の再現情報へ渡す原本、BOM除去等の解析用変換と区別 |
| SourceSpan | SourceFile識別、開始・終端byte offset。元表記は原本のsliceで参照 | diagnostic出力時にUnicode scalar列へ換算。BOMは列数へ加算しない、TABは1列、CRLFは1改行、始点を含み終点を含まない |
| TypeTable | NED完全修飾名→TypeDecl。宣言・default・属性・ポート・子・辺と各spanをprepareが所有 | 参照先確定後は不変。型属性の所有者は(type, QName)、パラメータ属性は(parameter, QName, name) |
| ExpandedStructure | root/compound/simpleのパス・親・型、各接続識別。解析ASTを変更せず別表へ展開 | compoundは構造、simpleは振る舞い。型宣言を共有しても実体の値・channel状態は共有しない |
| ResolvedModel | 実体ごとの正規値、登録descriptor、端点間routeと各辺のchannel参照 | 入力検証を全て通ったものだけPreparedInputへ移動。値・位置・元の型を失わない |
| PreparedInput | snapshot、凍結Registry参照、ResolvedModel、実行条件、profile検証済み負荷 | allocateの唯一の入力。失敗中のASTや未検証値をfactoryへ渡さない |

現行実装はClassical CANの`can.cc.ideal.v1`と、CAN間Gatewayを扱う`can.cc.multibus.v1`を受け付ける。入力層の内部実装は次の責務で分離する。

| ソース | 現行実装の責務 |
| --- | --- |
| `crates/dir-simulator/src/input.rs` | 公開`prepare`の進行、ファイル収集・snapshot、INIと実行条件、共通のJSON・時間変換を担当し、選択profileのアダプターへ渡す |
| `crates/dir-simulator/src/input/ned.rs` | NED構文・型付き値・包含・compound展開・接続経路・値上書き・共通FixedDelayを扱う。モデル固有規則は内部`ModelRules`を通して呼び、CANの型名・profile名・Bus個数・Controller生成を保持しない |
| `crates/dir-simulator/src/input/can.rs` | CANの宣言スキーマ・値制約・payload割当・profile整合、Bus/Controller個数と送受信対応、CAN実行設定への変換、workloadと受信フィルタを担当する |
| `crates/dir-simulator/src/input/gateway.rs` | CAN間Gatewayのmodel-config読込、port・route・担当ControllerとBusの照合を担当する |

prepareの戻り値は共有`lib/types/prepared.rs`の`PreparedSimulation`である。`common`へprofile選択・実行条件・取得済入力、`can`へCANのBus／Controller／Generatorと所属、`gateway`へCAN間Gateway／RouteとController所有を格納する。Schedule・Diagnostic・InputSnapshotは`lib/types/common.rs`、CANとGatewayの設定型はそれぞれのモデル別ファイルで宣言する。各入力moduleの単体試験は`input/tests.rs`、`input/ned/tests.rs`、`input/can/tests.rs`へ分離する。公開`types`パスとフィールド移行は[ソース配置](../アーキテクチャ設計書.md#source-layout)を参照する。

共通NED層は実体パス・型付き値・接続経路を持つ内部解決結果を返す。CANアダプターはその結果からCAN設定を組み立てる。全宣言のスキーマとdefault検証、実体の値解決直後のprofile照合、CAN個数検証後のchannel値解決という既存の検証順を維持する。これにより、INI上書きで不正defaultを隠したり、分割によって先に返す診断が変わったりすることを防ぐ。

この内部境界は公開Registryの実装ではない。将来profileの選択・JSON・coordinatorの全体契約は[複数モデル統合設計](複数モデル統合詳細設計書.md#prepare)へ委譲する。新しい通信モデルの固有規則もモデル別アダプターへ置き、一般パーサにモデルの個数条件を追加しない。

入力層分離の試験・変更前後比較は[検証記録](../verification/results/input-layer-split-2026-10-03.json)を参照する。共通層はCAN以外のテスト用モデル規則で検証し、実行互換性は既存CAN／Gatewayの設定を同じ入力のまま比較する。

| 処理 | アルゴリズム・判断 |
| --- | --- |
| 取得 | configをCLI cwd基準で解決し、ned-pathはconfigの親基準で`.`/`..`を正規化する。リンクを追跡する前に各対象を検査し、ルート・配下のシンボリックリンクを拒否。実在ディレクトリ、重複・包含、読み取り可否を検査する。ルート指定順、相対パスのUTF-8 byte昇順で隠しディレクトリを含めて収集し、小文字`.ned`の通常ファイルだけ取得。非NEDファイルを解析しない |
| 字句 | 原本のoffsetを進め、NED正本のID・予約語・最長一致・文字列・コメント・空白を適用する。コメントを文字列内で解釈しない。数値・単位・属性は独立tokenにし、元表記とspanを保持。未終端文字列／コメントは開始token、欠落EOFはEOF spanを返す |
| 構文 | NED正本のFile/Declaration/Parameters/Gates/Submodules/Connectionsを節順に解析しEOFまで消費。節の重複、kind別節制限、対象外予約語を判定。属性の配置・個数・引数を検査し、class/display/descriptionはstring解釈後のUnicode、unitは採用tokenで保持 |
| 型表 | 全ファイルを解析してから完全名を登録し、後続宣言も参照可能にする。同一QName重複は後発宣言を原因、先発位置を関連位置とする。packageと探索ルートに対する親ディレクトリが一致することを検査。異packageの同じ末尾名は別のTypeDecl |
| 参照・包含 | 子参照はsimple/module、channel参照はchannel、networkキーはnetworkへ種別照合。全宣言を走査し、未使用の未知型・包含循環も失敗。型包含graphを未訪問／訪問中／完了の三状態でDFSし、訪問中への辺を循環の原因として返す |
| 宣言検査と実体 | 全宣言の登録スキーマとdefaultを検査し、未選択型の必須値欠落は検査しない。選択networkだけを子宣言順の深さ優先で展開しrootは型末尾名とする。後段の値解決と全宣言の静的接続検査を含め、[診断準備順](../specs/診断詳細機能仕様書.md#lifecycle)に従って段階を分ける |
| 型と基準値 | ASTの宣言型・default literalは不変。実体にはTypeDecl参照と専用値表を作るため、Main.aのINI変更でMain.b又はTypeDeclのdefaultが変わる経路はない。simple/Bus/channelの能力は登録descriptorから受け取る |

内部の収集／解析／型解決は、それぞれ検証済みの前段データ又は位置付きInputErrorを返す。中途の表を公開せず、全宣言検査の完了を成功として記録する。型数V・包含辺Eの循環検査はO(V+E)、展開は生成実体数に比例。最大値を独自に追加せず、検出可能なメモリ確保失敗の分類は診断仕様へ従う。

## 3. ポート・compound境界・channel・実行所有

```trace

  "upstream": ["architecture#arch-model-loading", "architecture#arch-node-model"],
  "state": "confirmed",
  "pending": []

```

| 内部表・処理 | 所有権・手順・不変条件 |
| --- | --- |
| PortDescriptor | simpleは登録descriptorの(name,direction,protocol,message,version)を採用し、NEDの名前・方向集合を照合する。ノード全体のcapability名による一括適合に置き換えず、実際の各ポートで判定 |
| ConnectionSide | (owner path, gate, inner/outer)をkeyに出現数・辺識別・spanを持つ。simpleは一側、nonroot compoundは独立する内側と外側。compound inputは内側始点／外側終点、outputは逆。root networkにgateがあれば拒否 |
| 端点解決 | 接続を所有するcompoundとその直下の子だけを検索。子ノード→gate→方向→接続側重複→登録型適合を検査し、各側の必要接続数を確認する。祖先／孫への直接アクセスを許さない。未選択networkとmoduleも静的に検査するが、独立moduleの外側未接続は検査対象から除く |
| Route | simple outputからcompoundの内外側の対応を経由してsimple inputまで追う。全境界側も走査し、simpleと切り離された閉路を含め訪問側集合で循環を検出。終端欠落、protocol/message/version違いはinvalid_connection。routeは始終ポート、辺の順序列、channel参照を保持し、配送時に再探索しない |
| Connection / channel | keyは親パス::始点表記。型定義と辺の実体を分離し、channelの値表・生成後の状態は辺別所有。同型再利用又は境界内外で状態を共有しない。値解決後に各routeのdelayをchecked加算し、u64超過を準備失敗として返す |
| CAN構成 | v1.0.0ではBus宣言のinput/output数が同数かつ各二つ以上であることを検査し、メッセージ種別を方向から決定する。各Bus outputのrouteを一度たどり、到達したController.rxをキーにBus・出力ポート・受信経路を索引化する。各Controller.txの到達先がBus inputであることを確認し、索引から同じControllerの受信元を求め、送受信のBus一致・全ポートの一意な使用を検証する。名前の接頭辞・接尾辞・宣言順による対応付けは行わない。境界を含む送受信routeのdelayをそれぞれ合算して既存のController設定へ渡す。単一／複数Bus条件はprofile validatorで扱い、CAN判定は汎用route構築の外に置く |
| 安定IDと所有権 | simpleの正規パスをUTF-8順でNodeIdにし、PortId/ConnectionIdは[実行設計](実行詳細設計書.md#registry)の独立名前空間へ渡す。root/compoundは静的構造IDで保持しfactoryを呼ばない。実行後はEngineがsimple arena・ポート配送表・各channel実体を所有 |
| 能力の受渡し | Controllerのtx/rx・queue等の能力とBusの仲裁は同じ時刻・イベント契約へ接続される。TypedRouteにはschema名・版とdelay capabilityを固定し、[dispatch](実行詳細設計書.md#dispatch)へ宛先とportを渡す。入力層はcallbackを実行せず、CANの送信側／受信側delayの一回適用は[CAN設計](CANモデル詳細設計書.md#state-machine)が担当 |

channel付き辺の存在とpayload適合、channelのcapability適合は別の検査である。FixedDelayはdelay値をモデルへ提供し、入力層がフレーム占有や仲裁開始へ加算することはない。値0のchannelも明示辺ごとに生成する。

| 処理 | 内部の分担 |
| --- | --- |
| 行解析 | UTF-8/BOM/改行をSourceFileで扱い、行をSP/TABだけtrimする。空行・行頭コメントを除き、節又は最初の引用符外`=`で分割。一行の残りまで完全消費し、引用内の`=;#`を区切らない。NEDのコメント規則を流用しない |
| RawConfig | Generalは一回必須、Channel節は接続識別をkeyに一回のみ。実行キー・完全インスタンスパラメータキー・channelパラメータを別mapへ分類。各mapの値は生literalとspan。重複は値が等しくても後発key/節を原因として拒否 |
| パス | configの親を基準にquoted ned-path list、workload/model-config一個のquoted pathを解釈。一度だけstring escape解釈し、Unicode・大小文字を保持、`.`/`..`を正規化。空／制御文字のpathを拒否し、通常ファイル又はNEDルートの種類とリンク条件を検査 |
| 対象の照合 | Generalのkeyは最後の`.`でinstance pathとparameter名へ分離。ExpandedStructureにrootを含めて照合し、unknown_instanceとunknown_parameterを区別。Channelは存在する接続識別→明示channel→宣言パラメータの順。channelなしの辺に設定しても暗黙生成しない |
| 実行条件 | 必須network/ned-path/sim-time-limitと、metrics-window/max-events/max-delta-cyclesの既定値を別のRunConditionsへ格納。Tと観測窓は整数ps、上限は正のu64。値変換は次節を共用。省略workloadは空生成器、指定した不存在workloadは取得失敗 |
| 時間境界への引渡し | sim-time-limitを変更せずschedulerのTへ渡す。入力側が枯渇時刻にTを短縮する経路はない。T=0は正常入力で、[scheduler](実行詳細設計書.md#scheduler)が初期化後に[0,T)を適用する。イベント枯渇を含む終了理由は実行側で判定 |
| snapshot | NED/INI/負荷と追加profileの構成入力のbytes・正規path・確定値をPreparedInputへ移す。結果メタデータ側は同じ取得bytesをhash化する。実行開始後にパスを再読込して入力が置き換わる経路は設けない |

| データ・操作 | 内部規則 |
| --- | --- |
| ResolvedValue | declared_type、physical_quantity又はnone、normalized_value、adopted_source(INI/default)、adopted_span、declaration_span、default_span任意を保持。dimensionless intはi64、doubleは有限binary64、bool/stringは各所有値、量付きはu64 ps/bps/byte |
| 順序 | 全宣言のdefaultも宣言型・unit・登録値域で検証してから、選択実体の完全パス・パラメータ名UTF-8順に解決。有効INI→default→missing_valueの順で採用。INIが有効でも不正defaultを隠さない。未選択型にdefaultがないこと自体は有効 |
| literalの型 | int/double/bool/stringを正本の字句と完全消費で判定。無単位intはi64、実行上限は独立してu64へ変換。doubleの指数、NaN/Infinity、負符号付き数値ゼロは拒否し、intの-0は0。stringは指定五種類のescapeだけを一度解釈 |
| 量の変換 | 十進字句を符号付き整数係数nと小数桁kへ分け、採用単位係数mを乗じてn*m/10^kを任意精度整数で計算。負値・余り・u64超過を検査し、余りを丸めない。unit属性の物理量と入力単位を照合してからモデル固有値域を検査 |
| 無単位double | 正確な十進数からbinary64へties-to-evenで一回変換。無限大又は非零→0のアンダーフローを拒否。量付きdoubleはbinary64を経由せずu64へ正確換算し、宣言型doubleを別途保持 |
| 値域 | queueCapacity/bitrate/処理遅延/rxFilterは[CAN正本](../specs/models/CANモデル詳細機能仕様書.md#controller)のvalidatorへ渡す。一般表現で有効な値でもモデルが認めない値はinvalid_range等の準備失敗。新しい許容範囲をここで定義しない |
| 失敗位置 | 型・単位・範囲は値token全体、未知対象はkey、必須実行key欠落はGeneral節、必須parameter欠落はNED宣言。採用元とdefaultの位置を独立に保存するため、隠された不正defaultの原因をINIへ誤対応しない |

正規値は実体別で保持し、異なる単位表記が同じ整数になることを期待値とする。JSONへのu64量は[設定仕様](../specs/設定詳細機能仕様書.md#values)どおり十進文字列と明示単位へ渡す。結果ファイルのschemaと記録先は結果仕様が所有する。

| 境界 | 手順・失敗の扱い |
| --- | --- |
| 二段照合 | Registryのmodule/channel key重複を検査して凍結し、NED QName→escape解釈後@class key→kind付きdescriptor/factoryを結ぶ。異packageの同じ末尾名を結合しない。同じ実装keyの複数NED型での再利用は有効。パラメータ集合・宣言型・unitとポート集合・方向を照合し、default有無・宣言順・displayをschema同一性へ混入しない |
| prepare gate | 引数・取得→字句/構文→型と登録/schema→値→接続とprofile検証を[診断正本](../specs/診断詳細機能仕様書.md#lifecycle)の順で完了。全宣言と選択実体の検査を両方通過し、負荷も検証して初めてPreparedInputを返す。追加profileのJSON・workloadは統合設計の順序で検証 |
| エラー伝播 | InputErrorはreason、target、span任意、関連位置、actual/expected等を所有する。E-0001/phase=prepare、time_ps/event_seq=nullの共通Diagnosticへ一回だけ変換し、最初の不正で停止。原因段階を飛ばした派生診断を追加しない。取得不能はsourceだけ、位置null。unknown_typeとimplementation_missingを区別 |
| 停止条件 | 準備失敗はprep_failed/exit2、イベントcallback数0。入力検証段階ではfactory・initializeも0。出力先の失敗はE-0003/exit4の別境界であり、入力E-0001へ変更しない。diagnosticの公開・部分結果はライフサイクル／結果設計が担当 |
| allocate / initializeへの移管 | 検証済みsimpleと辺channelのdescriptor・正規値・安定IDを[実行Registry](実行詳細設計書.md#registry)とライフサイクルへ渡す。simpleはNodeId順に生成・初期化し、compoundはfactoryなし。channelは辺別所有。初期イベントは全初期化成功までは実行されない |
| 生成後失敗 | allocation_failed/initialize_failedはphase=allocate/initializeとして後段へ返す。成功済み初期化の逆順finish、全割当の逆順解放、基底journal未公開、イベントcallback数0は診断ライフサイクル正本に従う。入力層は失敗後の再生成・実行を行わない |
