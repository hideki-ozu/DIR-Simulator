## 収集・検証・処理フロー

1. trusted SHAとmain ref、main policy bytes、PRのrepository・actor・base/headを照合します。base...headのmerge baseがtrusted mainであることを要求します。
2. PRファイル一覧を全ページ取得し、changed_filesと照合します。[API上限3000件](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests-files)以上、途中取得、重複、不一致は停止します。Git treeも全体を取得し、truncatedなら停止します。
3. treeの実差分がファイル一覧と一致し、旧新とも通常blob/mode100644であることを確認します。削除、120000 symlink、100755 executable、160000 submoduleは拒否します。renameは旧新両パスの完全一致allowlistが必要です。blob bytesをGit形式でhashしtree SHAと照合します。
4. Markdownのraw HTML・危険URI・外部画像、INIのinclude・未知設定・外部参照、JSONの未知schema・過大件数を拒否します。PNGはCRC・chunk・終端を検査し、Pillow12.3.0で完全decode/re-encodeします。隔離ビルドには再エンコード画像を使います。
5. trusted-mainの`build_guide_inputs.py --check`、MkDocs strict、リンク検査、`verify_guide.py`を実行します。固定CLIで3サンプルの数値・manifestを再現します。ZIPは対象外なので、入力変更が既存ZIPと一致しなければ停止して人のレビューへ戻します。
6. 必須checkは`MkDocs strict build and links`と`Guide scoped validation`です。mainとheadのworkflow blob一致、正しいworkflow path/ID、pull_request event、repository、PR、head SHA、最新run/attempt、job/check/suite、GitHub Actions app ID15368を照合します。旧成功の後の失敗・queued・skipped、同名偽check、重複、欠落、取得不能は停止します。
7. 有効なmain rulesetにstrictな必須checkと提供元、delete/force禁止、bypassなしを要求します。writer起動runもAPIで再取得し、対象PRが一つだけで、最新検証runと同一であることを確認します。
8. PR・main・rules・全ファイル・checkをもう一度収集し、最初の結果と一致する場合だけ[head SHA指定の通常マージ](https://docs.github.com/en/rest/pulls/pulls#merge-a-pull-request)を実行します。追加commit、base移動、conflict、mergeable不明は停止します。
9. merged commitとmain refを確認後、main限定Pages dispatchにexpected_shaを渡します。dispatch run、build/deploy job、deployment SHAとrun URL、main refを追跡してから成功を報告します。

ネットワーク取得不能や未知のAPI形状も許可へ倒さず停止します。通信結果不明のマージやdispatchは再送しません。マージ済み・dispatch結果不明などの部分成功はauditに記録し、「公開成功」とは報告しません。

## Pages接続と権限

[GITHUB_TOKENによる通常イベントはworkflow再起動を抑制](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)するため、botマージ後のpushだけには依存しません。Pages dispatchはmain、repository変数`GUIDE_SCOPED_MERGE_ENABLED=enabled`、expected_shaとgithub.shaの一致が必要です。既存のmain push公開とPR deployスキップは維持します。

REST API version2026-03-10の[dispatch応答](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event)のworkflow_run_idを追跡します。run IDのない曖昧な応答では停止します。異なるcommitのrunやdeploymentを成功扱いしません。

将来writerに必要な権限はcontents:write（通常マージ）、actions:write（dispatch）、pull-requests:read、checks:readです。検証jobは読み取りのみです。repository全体の権限引き上げ、Administration権限、新規PAT/App/OAuth、保護解除は含めません。ネイティブallow_auto_mergeはfalseのままで構いません。
