文書ID：`tool-viewer-manual`

文書状態：公開仕様。CAN/GWを中心に、Ethernet・CAN FD・transaction画面の正本と検証範囲へ接続する。

本書はCAN/GW画面の操作を中心に説明する。Ethernet画面は[Ethernet負荷・QoS詳細機能仕様書](../../specs/models/Ethernet負荷・QoS詳細機能仕様書.md)、[EthernetVLAN・マルチキャスト詳細機能仕様書](../../specs/models/EthernetVLAN・マルチキャスト詳細機能仕様書.md)と[READMEのEthernet実行例](../../../README.md#ethernetサンプルを実行する)を参照する。transaction画面は[viewer仕様書](viewer仕様書.md)の「AXI・SoC・メモリ／IPCの結果」を参照する。

本書は結果ビューアの作成と操作を説明する。表示の契約、内部の復元方法、受け入れ確認は[viewer仕様書](viewer仕様書.md)を参照する。以下のコマンドはリポジトリのルートから実行する。

## 1. 結果を開く

既存の`results.json`があれば、CLIで単独HTMLを作る。出力先には存在しないファイル名を指定する。

```bash
cargo build --locked --release -p dir-simulator
./target/release/dir-simulator view \
  --input results/results.json \
  --output results-viewer.html
```

`results-viewer.html`をブラウザで開く。WSLからWindowsの既定ブラウザで開く場合は次を実行する。

```bash
explorer.exe "$(wslpath -w "$PWD/results-viewer.html")"
```

サンプルの結果を先に作る場合は、未存在の出力ディレクトリを指定して`run`を実行し、その`results.json`を`view`へ渡す。

```bash
./target/release/dir-simulator run \
  --config examples/gateway/fanout.ini \
  --output results-gateway
./target/release/dir-simulator view \
  --input results-gateway/results.json \
  --output gateway-viewer.html
```

HTMLには結果と入力スナップショットが埋め込まれ、ブラウザでの表示にサーバーや追加パッケージは不要である。元の結果とmanifestは変更されない。HTMLを別の環境へ渡す場合も同じ記録を表示できる。CLIはブラウザを自動起動しない。

代わりに[ビューア本体](../../../crates/dir-simulator/src/tool/viewer/assets/index.html)を直接開き、「results.json を選択」から結果を読むこともできる。この方法では同じフォルダの`style.css`、`model.js`、`ethernet-model.js`、`ethernet-app.js`、`transaction-model.js`、`transaction-app.js`、`app.js`を一緒に保つ。いずれの方法もファイルはブラウザ内で処理され、外部通信を行わない。

## 2. 時刻と通信を読む

「▶ 再生」で観測期間を連続再生し、「Ⅱ 一時停止」で止める。速度は0.25×、0.5×、1×、2×、4×から選ぶ。1×では観測期間全体を約8秒で表示する。これは画面上の速度で、実通信の速度ではない。連続再生中はメッセージの移動ではなく、送信線を青、受信線を橙、通常の接続を灰にして方向矢印を表示する。直近の完了も短時間だけ強調する。

スライダー、時刻指定、タイムラインのクリックで停止位置を選べる。時刻はµs、ns、ps、ms、sを切り替えられ、内部ではps整数の精度を保つ。時刻指定欄には選択した単位で0以上の数値を入力する。1 psに換算できない小数や観測範囲外の値は入力エラーになる。集計・ノード状態は選択時刻までに確定した内容で、タイムラインと詳細欄の時刻は実行全体の記録である。「部分結果」が出た場合も、未確定の予定EOF・予定解放を完了として表示しない。

「前のイベント時刻」「次のイベント時刻」または左右キーで記録時刻ごとに移動する。同じ時刻の記録は一つの時刻として扱い、内部イベントの順番は再現しない。どちらの方向から移動しても、移動先の直前の記録時刻から移動先までを同じ方向で再表示する。最初の記録時刻には再表示区間がない。送信はController→Bus、受信はBus→Controllerへ各約0.7秒で動き、両方ある区間は計約1.4秒になる。受信だけの区間は受信から始まる。Gatewayを通ると親CANの受信、Gateway入口→内部転送点→出口、出口CANの送受信へ進み、分岐ごとに経路を分ける。出口TX受理前の枝には内部受信が出ず、TX容量待機は入口に表示される。遅延ゼロの同報受信は受信先ごとに動く。アニメーション中の件数は移動先の確定状態である。

「ノードとパケットの流れ」ではControllerとBusの接続、Gatewayを囲むブロック、内部の論理経路を確認する。構成図の線・メッセージを選ぶと要求詳細へ進める。古い結果でtopologyがない場合、通信記録から復元した接続に加え、通信記録のないノードの接続は「推定CAN接続」として区別される。狭い画面ではGateway内のControllerが縦並びになる。

## 3. 要求とGatewayを調べる

通信タイムラインはノード別TX/RX、バス占有・間隔、送信待機、GW RX保持、破棄を示す。「＋」「−」「全体」で表示範囲を調整し、区間を選ぶと要求詳細へ進む。描画は最大500区間で、省略数を表示する。

要求一覧はID・ノード検索、現在時刻の状態フィルタ、75行ずつのページ移動に対応する。行を選ぶと、生成・SOF・EOF・解放・受信時刻と元レコードを見られる。時刻が「未確定」なら到達記録がない。予定時刻は実到達と区別する。

schema 2では「Gateway転送」にRX入力Controllerごとの容量・保持数・破棄数、経路ごとのGW処理・TX容量待機・コピー生成・hop破棄・RX破棄・経路不一致を表示する。コピー要求を選び、元要求・親要求との関係や終端Controllerまでの経路遅延を確認できる。転送一覧は受信時刻順の最新500行を表示する。表示上限や検索条件は構成図の動きと状態集計の母数を変えない。

## 4. 別の結果とエラー

「結果ファイルを開く」から別の`results.json`を選ぶか、画面へ1ファイルをドロップして切り替える。ここまで説明したCAN/GW画面はschema 1の`can.cc.ideal.v1`とschema 2の`can.cc.multibus.v1`で使う。schema 2のEthernet系profileはEthernet画面、AXI・SoC・AHB・NoC・メモリ／IPC系profileはtransaction画面へ切り替わる。未対応のschema/profileや不正なレコードは読込エラーになる。

CLIで「Viewer output already exists」と表示されたら、新しい出力ファイル名を指定する。親ディレクトリがない場合は先に作成する。入力JSONが読めない、構文が不正、schemaが対象外の場合は入力側を確認する。HTMLは作成できてもブラウザで読込エラーが出る場合は、結果の要求・受信・Gatewayレコードまたは時刻の整合性を確認する。結果を編集して直す前に、生成元の[結果仕様](../../specs/結果詳細機能仕様書.md)と[GW仕様](../../specs/models/GWモデル詳細機能仕様書.md)を参照する。

## CAN FD・Ethernet媒体profileの表示

`ethernet.l2.store-forward.v2`と`ethernet.l2.100base-t1.v1`はEthernet画面へ切り替える。物理linkのmode/duplex/role/PHY遅延、試行数・衝突数、試行ごとのSOF・collision・jam・backoff、MAC/MDIの予定時刻と成功実績を表示する。衝突試行から正常受信を作らず、停止時の未到達EOF・jam終了・arrivalを補完しない。前後ステップは移動先の直前区間を同じ向きで再表示する。

`can.fd.precomputed.v1`はController→Bus→受信先の画面を使い、二速度・DLC・BRS・外部位相bit数・evidence・binding SHA-256を詳細へ表示する。`fidelity=externally-precomputed-phase-bits`、`wire_validation=structural-only`を明示する。静的frame行があっても生成時刻が停止境界以後なら送信要求を作らない。任意profileの汎用codecではなく、対応する3種のFDレコードを検証して共通の記録時刻再演へ接続する。

これらのprofileは公開版v1.1.2以降の結果を開ける。CAN FDの例は[CAN FDのデータ速度比較](../../guide/CANFDのデータ速度比較.md)を参照する。

## 選択要求の記録時刻へ進む

1. CAN/GWのタイムライン又は要求一覧から追いたい要求を選ぶ。
2. 詳細の「この要求の記録時刻」で、生成・送信・受信・GW RX保持などの確定記録と対象ノードを確認する。
3. 時刻の「ps へ移動」を押す。要求の選択を保ち、再生を停止してその時刻の状態・タイムラインを表示する。キーボードではボタンへTabで進み、Enter又はSpaceを使う。

同時刻の記録はひとつにまとめている。並びから同時刻の内部処理順を推定しない。予定値は移動先に含まれない。GWの親要求を選ぶとその親の受信とRX保持を含み、コピー要求を選ぶとそのコピー自身の時刻を表示する。origin全体の別枝は含まない。別要求の選択・選択解除・ファイル切替で一覧も切り替わる。全体の「前のイベント時刻」「次のイベント時刻」は従来どおり全要求の記録時刻を移動する。

再生中も記録時刻ボタンにTabで進み、Enter又はSpaceでその時刻へ移動・停止できる。時間の表示更新でボタンのfocusを失わない。

## 同一区間のバス・キューを比較する

Classical CAN / GW 結果を開き、「同一区間のバス・キュー比較」で「全期間」または「タイムライン表示区間」を選ぶ。後者はタイムラインの拡大・縮小・移動に追従する。表の `[開始, 終了) ps` と長さを確認する。要求検索やページを変えても集計は全記録のままである。

バス表の TX 占有時間・割合と Intermission を分けて読む。未完了件数は観測終了で打ち切った区間を示す。ゼロ長の割合は未定義。Controller TX と Gateway RX は別表であり、出口受付前の RX 保持を TX 待機へ二重計上しない。

キューは「再演状態最大」「非空合計」「非空最長連続」を併記する。最大は同時刻の最後の計測による状態であり、全記録の `queue_max` とは異なる。開始以前の計測がない N/A は 0 と区別する。期間は ps、割合は小数第3位まで切り捨て表示する。

並び順で最大・合計・最長を比較し、最大の最初の時刻または最初の非空時刻を押す。再生が停止し、その時刻のノード状態へ移動する。バスの最初の TX は対応要求の詳細も選択する。開始前からの待機ならリンク時刻は区間開始になる。時間リンクはキーボードでも操作でき、手入力・巻き戻しと同じ状態を表示する。比較表は横スクロールできる。新しいファイルを開くと区間と並び順は初期状態へ戻る。

定義と算出条件は [Viewer仕様](viewer仕様書.md#cangw-の同一区間比較)、検証記録は [Issue #53 実画面・回帰検証](../../verification/results/viewer-intervals-2026-10-11/report.md) を参照する。

バス比較の時刻リンクから別要求へ移る場合は、既存の要求選択処理で詳細・ネットワーク・要求表・タイムラインを同期する。全範囲表示で時刻が既存表示区間内にあっても、新要求のバーを強調し、旧要求を減光する。ブラウザ回帰では Bus B の要求選択から Bus A のリンクへ移動し、選択ID・時刻とバーの stroke / opacity を照合する。

## CAN↔Ethernetをorigin全体で追う

本節はIssue #109で追加する操作であり、既存のv1.1.6公開物には含まれない。

`can.ethernet.gateway.v1` の結果を開き、「CAN媒体とGateway変換」で起点originを選ぶ。「このoriginの記録時刻」に、読み込んだrunの確定済み時刻が表示される。CANとEthernetに同じIDがあっても、`can:`／`ethernet:`付きoriginで区別できる。各行の媒体、port／Gateway、枝lineage、理由を確認し、対象ボタンから対応する詳細を開く。terminal完了は受信行にorigin・segment・枝・terminalの組で併記される。

「…psへ移動」を押すと再生とステップアニメーションが停止し、その時刻の状態へ移る。ボタンはEnter／Spaceでも操作できる。巻き戻すと後続行は「現在時刻以後」となるが、run内に確定記録があるため引き続き移動できる。予定EOF／予定readyだけの時刻や未生成の子は表示されない。同時刻内の行順は処理順を表さない。

一覧はorigin全体を対象とし、VLANや転送検索、表や図の描画上限では絞られない。長い一覧は独立してスクロールできる。origin変更で一覧が切り替わり、詳細の「解除」でoriginも解除される。ファイル切替や不正結果の読込では以前の移動先を消す。全体の前後ボタンは従来どおり全originのイベント時刻を移動する。

CAN要求の詳細では「現在時刻の状態」と「実行終了時の記録状態」を別々に確認できる。前者はCAN実績カードと同じ再生位置の状態で、巻き戻すと生成前や処理中へ戻る。後者は読み込んだ結果に保存された最終状態を保つ。詳細JSONでも`status`と`recorded_status`を区別し、受信先の状態も同じ再生位置で表示する。最終状態がsuccessやdroppedでも、現在時刻で送信・破棄済みとは限らない（Issue #122の表示修正）。
