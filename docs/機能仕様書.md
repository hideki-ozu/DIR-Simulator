### 2.1. 上位要件を満たす工程間の受け渡し

[要件定義書の利用フロー](要件定義書.md#22-利用フロー)を、以下の受け渡しで具体化する。各工程の内部契約は第1章の正本に置き、本書では工程を組み合わせたときの確認範囲を示す。

| 上位要件 | 機能を組み合わせた処理 | 次工程へ渡す条件と共同確認 |
| --- | --- | --- |
| [構造定義](要件定義書.md#dir-req-0005) | NED収集、型・階層展開、ポート・接続検証 | 選択networkの全インスタンスと接続を識別でき、デフォルト値を設定解決へ渡せること。構文受理だけで構造定義の充足とはしない |
| [実験条件の初期化](要件定義書.md#dir-req-0006) | INI選択、値の優先・型・単位検証、実装登録、生成・初期化 | 同じ構造に異なる条件を適用し、上書き値と保持値が生成された各モデルに届くこと。検証成功と初期化成功を区別する |
| [離散イベント実行](要件定義書.md#dir-req-0007) | 時刻順配送、モデル処理、遅延・有限資源、終了制御 | 入力要求から確定した状態変化までを再現し、終了時の未完了を結果へ渡すこと。各モデルの仲裁と共通スケジューラの順序を両方確認する |
| [評価結果の取得](要件定義書.md#dir-req-0008) | 時系列、集計、意味情報、CSV・JSON、失敗通知 | 同じ要求・対象・観測区間を記録間で対応付け、入力条件から結果を読み戻せること。ファイルの存在だけでは意味付けや完全性を満たさない |

入力診断、再現性、異常終了の識別は複数工程へ適用する。上位要件への機能割当は、子の割当から暗黙に継承せず、第11.2節と各詳細仕様の`trace`で実際の担当を追跡する。

### 11.3. 判定の境界

有効要件205件・機能54件の対応を記録する。当初の全対象と共通実行・拡張統合・媒体拡張、負荷・QoSと次段階VLANの詳細仕様・設計・検証手順を接続した。CAN/GW・Ethernet L2/QoSの製品試験は各モデルの実行記録で管理する。VLAN・媒体v2・CAN FD・100BASE-T1の製品試験も独立の実行記録で管理する。他の未実装モデルは検証手順までの設計であり、性能・規格全体適合は別途確認する。構造検査の成功はシミュレータの実行合格を示すものではない。
