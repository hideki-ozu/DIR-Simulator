## 1. 要件

<a id="p-composite-r01"></a>
**P-COMPOSITE-R01**：明示した単一profileでClassical CAN／Gateway／dynamic Ethernet／TAS・CBS・PSFPを準備し、資源とportの重複所有、設定矛盾、未承認組合せをrun前に拒否する。

<a id="p-composite-r02"></a>
**P-COMPOSITE-R02**：一つのFESで変換→一回のpolicing→容量入場→TSN選択を行う。満杯待ちとgate/credit待ちを分け、枝単位の通常dropとcallback全体の失敗を区別する。

<a id="p-composite-r03"></a>
**P-COMPOSITE-R03**：conversion/branch/segmentの参照閉包、実SOFで固定するterminal母数、[0,T)の実績を保持し、失敗前prefixと原子commitを保証する。

<a id="p-replication-r01"></a>
**P-REPLICATION-R01**：単一送信源・一複製点・一除去点・2～16本の有限静的経路を明示し、stream・sequence・経路・履歴・pending資源を上限付きで準備する。

<a id="p-replication-r02"></a>
**P-REPLICATION-R02**：origin受付順の非巡回u64 sequenceと幅Nの履歴によりaccept/duplicate/staleを一意に決める。各枝は実媒体を独立消費し、一原frameのterminal成功は一回に限る。

<a id="p-replication-r03"></a>
**P-REPLICATION-R03**：branch/recovery/originの結果から複製量、除去理由、terminal母数を再構成できる。履歴更新とdeliverは同じ原子batchで確定する。

<a id="p-preemption-r01"></a>
**P-PREEMPTION-R01**：全二重portのclass分割・fragment量・overhead・gap・資源上限を明示する。preemptable CBS、半二重、Gateway/冗長配送との暗黙合成を拒否する。

<a id="p-preemption-r02"></a>
**P-PREEMPTION-R02**：fragment境界だけでexpressを選択し、単一のsuspended frameを順序を保って再開する。gate-fit、resume gap、整数ceil、時刻・世代の取消規則を決定する。

<a id="p-preemption-r03"></a>
**P-PREEMPTION-R03**：frame完了・fragment完了・express・gap・実媒体占有を区別し、未完成frameを成功へ補完しない。予約失敗時にqueue/fragment/FES/recordを部分更新しない。

## 2. 機能と初期scope

<a id="p-composite-f01"></a>
**P-COMPOSITE-F01**（R01）：CompositePrepareは単一のresolved Ethernet instanceへbridgeとTSNを接続し、schema・参照・所有者・上限を凍結する。

<a id="p-composite-f02"></a>
**P-COMPOSITE-F02**（R02）：ConversionAdmissionはcodecと分類を確定し、synthetic ingressのPSFPを一回評価し、Admitted/Waiting/Droppedを返す。EgressSelectionは通常TSNだけを使う。

<a id="p-composite-f03"></a>
**P-COMPOSITE-F03**（R03）：CompositePublicationは既存媒体別recordとcross-media lineage、terminal tuple、prefixを原子記録する。

<a id="p-replication-f01"></a>
**P-REPLICATION-F01**（R01）：ReplicationPrepareは静的source-routed circuitを解決し、正規path indexとstreamごとの単一sequence空間を固定する。

<a id="p-replication-f02"></a>
**P-REPLICATION-F02**（R02）：ReplicationPlannerは一originを同時に枝生成し、CircuitForwarderは各hopで通常TSN queueへofferする。RecoveryPlannerは除去点で受信処理完了した枝だけを有限窓へ適用する。

<a id="p-replication-f03"></a>
**P-REPLICATION-F03**（R03）：RedundancyPublicationはbranchの終端と原frameの一回deliverを分離し、historyとdeliverを同じNetworkDeltaに置く。

<a id="p-preemption-f01"></a>
**P-PREEMPTION-F01**（R01）：PreemptionPrepareは各outputのexpress/preemptable分割と量を検査し、profile専用transfer schemaを登録する。

<a id="p-preemption-f02"></a>
**P-PREEMPTION-F02**（R02）：FragmentSchedulerは通常class適格性とfragment-fitを用い、一つのport state machineで境界選択・再開gap・世代付きwakeを管理する。

<a id="p-preemption-f03"></a>
**P-PREEMPTION-F03**（R03）：FragmentPublicationは占有区間とgapを別々に記録し、最終fragmentだけが一回の既存L2受信へ進む。

初版は三profileを個別選択する。既存profileを配列指定して合成しない。冗長配送は複製点=送信Endpoint、除去点=宛先Endpointに限定する。中間任意switchでの複製/除去、複数talker、wire sequence tag、実行中reset、動的path変更は対象外。preemptionは静的全二重link、単一suspended frame、expressのCBSのみを許す。いずれもwire制御adapter、PHY/PAUSE/半二重と組み合わせない。

## 3. 詳細仕様

### 3.1. 共通の型・順序・上限

S=非空ASCII `[A-Za-z0-9_.:/@-]+`、port/deviceはNED完全パス。J=boolを除くJSON整数。D=`0|[1-9][0-9]*`のu64十進文字列。Uは同じ表記のu128。`?`は省略可能ではなく必須fieldのnull許可を表す。以下のobjectは列挙したfieldを過不足なく必須とし、未知/重複field、未知enum/version、null不可fieldへのnullをprepare拒否する。既定値はなく、空配列とnullの意味だけを明示する。既存schemaの既定値はそのvalidatorのまま継承する。時刻は整数ps、half-open [0,T)、算術checked u128、実予約時刻/世代/seqはu64。ceil(n/d)=n/d+(n%d!=0)、d=0拒否。u128 overflow、u64実時刻超過、ID/epoch枯渇はE-0004でcallback全体未commit。

FES keyは既存`(time_ps,delta,phase,seq)`。phase0でwire完了/release→link/STP→registration/membership→aging→GCL更新、phase1で到着/offer、phase2で選択。同phaseはcanonical source/path/port順に予約した既存seq順。phase2のSOFで起こるGateway再offerは次delta phase1で、同時刻に過去phaseへ割り込まない。phase0 fragment完了の後のphase1 express到着は同delta phase2から見える。

共通`limits={max_pending_branches:J,max_control_events:J}`は両方1..4294967295、必須。pending branchは「将来/待機/queue/activeで、終端がまだない単位」の数で、compositeは変換枝、replicationはpath枝、preemptionはqueue中又は送信/停止中のhop transfer一個を数える。上限を減らすAPIはない。branch終端drop又はhop/branch受信処理完了で枠を返す。max_control_eventsはprofile coordinatorの意味上有効なtimer/FES予約の同時総数（同一coordinatorへ畳み込むdue itemも各一件）で、単なるjournal件数ではない。予約取消時に枠を返し、古いtokenを残す場合も物理FES資源は既存Engine上限に従う。prepareで初期予約と静的fanout（一origin）を検査し、動的超過は通常queue dropへ変換せず成功prefix付き実行診断とする。

### 3.2. Composite入力とadmission

<a id="p-composite-s01"></a>
**P-COMPOSITE-S01**（F01）：候補profile=`can.ethernet.tsn.v1`。config exact root:

```text
{schema_name:"dir.can_ethernet_tsn.config",schema_version:1,
 bridge:{schema_version:1,can:{},gateways:Gateway[]},
 ethernet:DynamicEthernetConfigV4,tsn:TsnBodyV1,limits:Limits}
```

`bridge.gateways`は[既存変換schema](../../specs/models/CAN・Ethernet変換詳細機能仕様書.md#codec)の全fieldをそのまま使う。instance/can_ports/ethernet_endpoint/rx_capacity/conversion_delay_ps/max_hops/rulesを必須とし、ruleも既存exact schemaのまま。CANはClassical dataのみ、can={}。rx_capacity=0は通常rx_full、max_hops=1..255。codec/routeはprepare後不変。`bridge.ethernet`は存在を拒否する。

`ethernet`は[dynamic入力](../../specs/models/Ethernet動的制御詳細機能仕様書.md)のschema_version=4、exact root `schema_version/endpoints/switches/ports/outputs/dynamic`。`tsn`は[TSN入力](../../specs/models/EthernetTSN詳細機能仕様書.md#scheduling)のbodyそのもの、exact `clock/outputs/streams/gcl_updates`。clock=ideal_shared、全outputをstrict_priorityの8classで列挙、tas=nullなら全open、cbs=[]なら無し。TSN bodyを既存validatorへ渡すため内部で`{schema_version:1,base:{profile:"ethernet.l2.dynamic.v1",config:ethernet},tsn}`を構築する。この一時adapterを利用者設定として重複保存しない。

workload exact rootは`{schema_version:1,can:CanWorkloadV2,ethernet:DynamicWorkloadV4}`。dynamic workload exact `schema_version/generators/controls`、CAN/EthernetのGateway所有送信源をgeneratorへ指定することは禁止。規則から生成するVID/PCPはEthernet port policyで有効なものに限定し、priority=PCP（0..7）の既存classへ写す。新たなPCP→class mapping fieldは設けない。通常incoming streamの未一致は既存通りbypass。参照IDは解決不能なら拒否するが、全codec出力にstream定義を強制しない。compositeのEthernet native generatorはdynamic v4のframe.ip_multicast必須nullableも継承する。

**namespace詳細化の判断**：旧bridge rootはethernet schema3を内包し、TSNはdynamic schema4をbaseに持つ。両方を丸ごと保持すると同じqueueを二重定義するため、本案ではbridgeを上記projectionへ正規化する。旧`can.ethernet.gateway.v1`の入力は変更しない。Ethernet output queue容量はethernetだけを正本とし、NEDの既存device共通queueCapacityも別のport全class合計枠として有効。いずれも満たす必要がある。両者は同じ資源の再定義ではなく、既存のclass枠とport総枠である。

<a id="p-composite-s02"></a>
**P-COMPOSITE-S02**（F02）：変換readyでcodec/VID/PCP/egress wireを固定し、offer=ready+egress txProcessingDelayを一回加算する。CAN→Ethernetは既存のsource offerがPSFPを迂回するため、Gateway所有Endpointのrx完全パスをsynthetic ingress keyとして、offer callbackで一回だけPSFP評価する。これは実Ethernet receptionではない。PSFP recordの`reception_id`は同batchに作成する`dir.composite.ingress/1`のIDを指す。通常wireでそのrxへ到着したframeは通常ingressで一回評価済みであり、Ethernet→CAN変換で再評価しない。synthetic ingressは受信母数・link bytes・rxProcessingDelayを追加しない。

| conversion/branch状態 | 入力・guard | action・次状態 |
| --- | --- | --- |
| 未存在 | 通常媒体受信通過、codec/lineage/rule/RX検査成功 | RX+1、processing、ready予約。RX0/満杯ならrx_full終端、予約なし |
| processing | ready、epoch一致 | 全枝をcanonical egress順で作成しcodec/PCPを固定、各offer予約。ready=offerなら同callbackで続行 |
| 未offer | Ethernet offer、PSFP未評価 | synthetic ingress recordとPSFP差分を一回作成。dropならbranch dropped/psfp_*、queue増分0 |
| 未offer又はwaiting | policing pass/bypass済、class容量0/port総容量0/M>capacity_bytes | dropped/tx_unadmittable。token返却なし |
| 未offer又はwaiting | policing済、class件数/bytesとport総件数に空き | Admitted、child frame/transfer作成、queue+1。gate/CBSを見ない |
| 未offer又はwaiting | policing済、有限容量満杯 | Waiting。wire/childは計画値だけ、token再消費なし。未来時刻を周期pollしない |
| Admitted | phase2でTSN適格、SOF開始 | queue-1、枝sof実績、segment対象凍結、全class待機枝を次deltaへwake |
| processing/waiting_tx | 各枝のAdmission又はdrop確定 | 未確定枝だけ待つ。全枝Admitted/DroppedならRX-1/released（SOFを待たない） |
| released/dropped | 旧ready/offer/wake | 状態変更なし、record/metric追加なし |

Waitingの順は既存`(offer_ready,origin_id,conversion_id,egress_path)`。offer_readyはegress遅延を加算した時刻で固定する。wake時は全classの全待機枝をこの順で走査し、満杯枝だけを残す。PSFPを再度評価しない。CAN egressは既存bridge待機/仲裁を継承し、PSFP/CBSを適用しない。通常wire ingressのPSFP拒否は媒体受信段階のdropで、Gateway RXを予約しない。admission後のdynamic不適格はEthernet copyの通常dropであり、既にreleasedのGateway RXを戻さない。

<a id="p-composite-s03"></a>
**P-COMPOSITE-S03**（F03）：外側output_schema_version=2、既存5ファイル/manifest-lastを維持。既存CAN request/receiverとbridge conversion/branch/segmentに、dynamic Ethernet5種・TSN4種とsynthetic ingress1種を登録する。変換profileが従来使うethernet.frame/3・transfer/3・reception/2の代わりにdynamicのvisit ID付きschemaを使うことをmetadataへ明記する。同じ文字列IDでも(schema_name,record_id)を参照キーにする。terminal tupleは実SOFだけで凍結し、TSN待機・fragment・synthetic ingressを別origin/成功へ数えない。

`dir.composite.ingress/1` dataのexact fieldsは`ingress_id:S,conversion_id:S,branch_id:S,ingress:S,child_planned_id:S,stream_id:S?,vid:D,priority:D,mac_bytes:D,offered_ps:D,verdict:"pass"|"bypass"|"drop",reason:S?,effect_seq:D`。drop理由はPSFP既存4種、pass/bypassのreason=null。IDはlength-prefixed `("synthetic",branch_id)`。既存TSN policing/1のreception_idはこのprofileだけsynthetic ingress又はdynamic receptionを参照し、metadataの`policing_reference_schemas=["dir.composite.ingress/1","ethernet.dynamic.reception/1"]`で参照先を列挙する。synthetic IDは先頭component="synthetic"の長さ付きnamespaceへ予約し、native/dynamic reception IDとの重複をprepare/作成preflightで拒否する。全branchのpolicing/drop/queue/RX/FES/recordを同じcallback batchへ入れる。PSFP dropをconversionとpolicingで二重に「一枝drop」集計しない。segment参照と完了母数は既存[変換結果仕様](../../specs/models/CAN・Ethernet変換詳細機能仕様書.md#runtime)を完全継承する。

### 3.3. 冗長配送の設定・有限履歴

<a id="p-replication-s01"></a>
**P-REPLICATION-S01**（F01）：候補profile=`ethernet.redundancy.abstract.v1`、config exact root:

```text
{schema_name:"dir.ethernet_redundancy.config",schema_version:1,
 base:{profile:"ethernet.tsn.v1",config:TsnWrapperV1},
 replication:{streams:ReplicationStream[]},limits:Limits}
ReplicationStream={stream_id:S,source_generator:S,replicate_at:S,eliminate_at:S,
 history_capacity:J,egress_paths:[{id:S,ports:S[]}]}
```

全field必須、既定値なし。streamsは1件以上。stream_idとsource_generatorはrun内一意。一generatorは一stream、generatorはbaseの既存generator ID、replicate_atはその送信Endpointに一致、eliminate_atは別の宛先Endpoint。元frameのdst_macは除去Endpointのindividual MAC、IP multicast=null。history_capacity=1..65536、paths=2..16、path idはstream内一意。portsは1件以上のoutput完全パス配列、先頭device=replicate_at、各direction到達device=次portの所有device、末尾到達device=eliminate_at。中間deviceはswitchのみ、同一device再訪・同一port反復・同一ports列の重複を拒否する。全hopは全二重、bitrate>0、初期link_up、VID許可。path id辞書順にindex=0..K-1を固定。port列の入力順は経路そのものなので保存する。共有linkは許し、metadataの`shared_ports`へsorted集合を出す。経路独立性は保証しない。

workloadはbaseのDynamicWorkloadV4のまま、controls=[]を必須とする。静的GCL更新は許す。dynamic設定の初期VID登録・link設定は適用するが、本profileで実行中link/STP/membership/registration変更は未対応としてprepare拒否する。baseの既存periodic/burst/explicit generatorを使用し、利用者のsequence/reset入力fieldはない。

**経路解釈の判断**：同じSpanning Treeへ普通のFDB転送で枝を投入すると代替経路が抑止され、冗長path契約が成立しない。選択streamの枝だけを**静的source-routed circuit**としてforwardする。configured次hopだけへ一回offerし、FDB learn/lookup/flood/STP判定は行わない。各hopでVLAN/FCS/PSFPとqueue/TAS/CBSは通常どおり適用する。初期link/VIDはprepareで全hop確認する。通常の未選択generatorはbase TSNのL2経路のまま。これは規格bridgeのFRERではなく明示pathの抽象意味であり、metadataに`routing_rule="static-circuit-no-fdb-no-stp"`を必須保存する。

<a id="p-replication-s02"></a>
**P-REPLICATION-S02**（F02）：streamの初期`next_sequence=0,exhausted=false,high=null,bitmap=0`。generator ready（source txProcessingDelay後）でoriginを受け付ける。受付順はFES順、同時刻generatorは既存canonical generator ID順。sequenceを一回割当て、全K枝とoriginを同一batchで作成する。queue full等の通常dropで番号を返さない。seq=u64::MAXのoriginは受付可能で、そのcommit後exhausted=true、次受付は診断とし0へwrapしない。record allocation失敗時は番号も進まない。

first-hopと各中間hopのofferは通常Ethernet source/copyのdrop-newestで、容量0/過大=unadmittable、満杯=queue_full（GatewayのWaitingを流用しない）。各枝は独立にqueue容量を消費し、path index順で同batch staged queueを見る。各hopのwire MAC bytesに抽象sequenceを足さない。switch forward delay、endpoint rxProcessingDelay、link伝搬は既存規則で一回ずつ。hop indexは単調増加し、末端での再複製はしない。

除去点はFCS/VLAN/PSFP通過後、最後のendpoint受信処理完了callbackでrecoveryを評価する。端点アプリへのdeliverとhistory更新は同batch。PSFP/dropした枝はhistoryを触らない。同時刻の同seqは先にcommitしたFES seqの枝だけがacceptされる。

| 履歴状態・guard | decision | 次high/bitmap（bit iはhigh-i） |
| --- | --- | --- |
| high=null | accept_first | high=seq、bitmap=1 |
| seq>high、d=seq-high>=N | accept_advance | high=seq、bitmap=1 |
| seq>high、0<d<N | accept_advance | high=seq、bitmap=((bitmap<<d) AND ((1<<N)-1)) OR 1 |
| seq<=high、i=high-seq>=N | stale | 変更なし |
| seq<=high、i<N、bit i=1 | duplicate | 変更なし |
| seq<=high、i<N、bit i=0 | accept_late | high維持、bit i=1 |

N=65536でも巨大u64 shiftをしない。実装はN bit vector/word配列、d>=Nを先に分岐。seqの比較後にunsigned差を取る。N=1はhighと同じ番号だけ保持し、古い番号は全てstale。holeを待つtimer、age timer、reset、履歴eviction by wall-timeはない。

枝状態は`created→queued→in_flight→forwarding→queued…→delivered|duplicate|stale|dropped`。first-hop offerでdropならcreated→dropped。in_flightにはwire/伝搬待ち/受信処理待ちを含み、hop完了後に次hopがあればforwarding、最終ならrecoveryで終端。終端への旧callbackはno-op。branch枠は終端まで保持する。originのtarget_countは最初の実branch SOFで0→1、targetはeliminate_atに固定する（他枝SOFでは増やさない）。accept時completed_count=1、delivered_branch_idとcompleted_psを一回保存する。全枝dropでも未SOFならtarget0、どれかSOFならtarget1/completed0。stale枝のoriginは成功にならない。

<a id="p-replication-s03"></a>
**P-REPLICATION-S03**（F03）：追加schemaは次の3種、全version=1、外側schema2。共通envelopeは3.5に従う。

| schema | exact data fields |
| --- | --- |
| `dir.redundancy.branch` | branch_id:S, origin_id:S, stream_id:S, sequence:D, path_id:S, path_index:D, path_ports:S[], hop_index:D, current_transfer_id:S?, created_ps:D, first_sof_ps:D?, completed_ps:D?, status:上記enum, reason:S?, recovery_id:S?, effect_seq:D |
| `dir.redundancy.recovery` | recovery_id:S, input_branch:S, origin_id:S, stream_id:S, sequence:D, eliminate_at:S, decision:accept_first/accept_advance/accept_late/duplicate/stale, previous_watermark:D?, new_watermark:D, history_capacity:D, bitmap_before_hex:S, bitmap_after_hex:S, delivered:bool, effect_seq:D |

### 3.4. 分割送信の設定・状態機械

<a id="p-preemption-s01"></a>
**P-PREEMPTION-S01**（F01）：候補profile=`ethernet.preemption.abstract.v1`、config exact root:

```text
{schema_name:"dir.ethernet_preemption.config",schema_version:1,
 base:{profile:"ethernet.tsn.v1",config:TsnWrapperV1},
 preemption:{outputs:[{port:S,express_classes:J[],preemptable_classes:J[],
 fragment_payload_bytes:J,fragment_overhead_bytes:J,resume_gap_ps:D}]},limits:Limits}
```

全接続outputを一回列挙。classは0..7、配列内重複なし、両集合交差なし、和集合={0..7}、いずれの集合も空を許す。fragment_payload_bytes=1..4294967295、overhead=0..4294967295、gap=0..u64::MAX。どれも必須、既定値なし。preemptable classへのCBSは拒否、express CBSはTSNそのまま。workloadはDynamicWorkloadV4でcontrols=[]、base topology/link bitrate/VIDは固定、GCL更新は許す。フレーム長0/bitrate0はprepare拒否（既存MAC padding後の長さは通常64以上）。fragment量は**アプリpayloadではなくegress変換後の元MAC byte列M（FCS含む）を分割する量**。wireに標準fragment headerを生成せず、数量だけをモデル化する。

preemptable各fragmentはL=min(F,remaining)>0、`duration=ceil(8*(L+O)*10^12/R)`。Oは全ての追加抽象占有を含み、通常の8byte preamble/12byte IFGを更に足さない。Expressは既存Ethernetの`serialization=ceil(8*(M+8)*10^12/R)`、`occupancy=ceil(8*(M+20)*10^12/R)`を使用し、EOFとreleaseを分ける。preemptableではfragment end=fragment release、最終fragment end=frame EOF=frame release。各fragmentは元MAC byte列の連続sliceで、offsetを増やして再結合したM byteを最後の実arrivalで既存FCS/VLAN parserへ一回渡す。連続fragmentに追加IFG/gapはない。gapは空き媒体時間でbusyへ含めない。PSFPは元frameの実ingressで一回、各fragmentには適用しない。

<a id="p-preemption-s02"></a>
**P-PREEMPTION-S02**（F02）：初期state=Idle、active=null、suspended=null、offset=0、epoch=0、gap_due=null。portは一時点に高々一つの実送信を持つ。expressはclass数値の大小に関わらず全preemptableより優先し、同集合内は最大priority/FIFO。同classの後続は先頭を越さない。suspendedがあれば新preemptable frameは開始しない。既存TSNのdynamic eligibility、TAS、CBS適格性をexpressへ適用する。fragmentはpreemptable classのTAS、現在fragment durationと既知GCL更新境界に対するfitを適用する。end<=open_endを許す。express先頭が不適格なら他express class、次にsuspended/通常preemptableを検査する。queued but gate-blocked expressは媒体を無期限占有しない。

| state | 入力・guard | action・次state |
| --- | --- | --- |
| 全状態 | arrival/offer | 通常容量admissionだけ。active区間を変更しない。dirtyを立てる |
| Idle | selection、eligible expressあり | 一件dequeue（容量解放）、Expressへ。EOF/release/arrivalを予約 |
| Idle | selection、expressなし、eligible preemptableあり | 一件だけdequeue、offset0、fragment記録/完了予約、PreemptableFragmentへ |
| Idle | 候補なし/全不適格 | Idle維持、次fit/GCL/CBS候補の最小wakeだけ。never_eligibleなら将来変更まで予約なし |
| PreemptableFragment | 完了token一致、残量>L | offset+=L、activeからsuspendedへ、phase2選択。eligible expressならExpressへ、無ければgap無しで次fragment |
| PreemptableFragment | 完了token一致、残量=L | offset=M、元frame EOF/release一回、propagation後の実arrival一回を予約。suspendedなし、Idleで選択 |
| Express | EOF token一致 | express EOF実績だけ。IFG中もExpress、選択不可 |
| Express | release token一致、eligible expressあり | 次expressを開始。suspendedは維持しgapを開始しない |
| Express | release token一致、eligible expressなし、suspendedあり | Suspended/gapへ、gap_due=now+resume_gap。gap0は同batchで満了処理しphase2へ |
| Express | release token一致、suspendedなし | Idle。gapなし |
| Suspended/gap | gap未満のarrival、gate/control、selection | queue/dirtyだけ更新。expressもgap途中で開始しない |
| Suspended/gap | gap完了token一致 | gap完了、Suspended/readyへ。eligible express優先、開始したexpress群の後には新gap一回 |
| Suspended/ready又はgate_wait | selection、eligible expressあり | Expressへ、元frame保持 |

| 全状態 | 古いepochの完了/wake/gap | no-op、公開record/metric無し |
| 全状態 | callback計算/予約/参照失敗 | state/queue/epoch/FES/record全て旧値のまま、run Failed |

表のfragment完了とExpress releaseはphase0で状態を空けるだけで、実際の次開始はphase1到着を見たphase2で行う。「eligible expressあり」はそのphase2で評価する。express群の終了もそのphase2で確定し、そこでgapを開始する。gap_dueのeventはphase0、同時刻到着expressはphase1でvisible。gap未満に到着したexpressはgap_dueで選択、gap中に複数expressが来てもgapを延長しない。expressなしでfragmentが連続する場合は境界ごとにgap0。末尾fragmentで元frameが完了した場合、後続expressのためにgapを作らない。

port epochは新たなactive fragment/express/gap/wakeの置換時にchecked incrementし、tokenは(port,kind,epoch,id)。進行中のwire完了tokenをgate wakeの再予約で失効させないため、`tx_epoch/gap_epoch/wake_epoch`を独立に保持する。完了成功・予約取消で該当tokenを無効化、同時刻取消済み旧eventはno-op。GCL変更はactive送信を中断せずwake_epochだけ更新する。未計画の最終frame EOFを事前算出して結果へ置かない。

<a id="p-preemption-s03"></a>
**P-PREEMPTION-S03**（F03）：元queueから除くのは最初のfragment SOF一回で、suspendedはqueueへ戻さず容量を占有しない。receiverは最終fragment end+link delayで一回observed、その後rxProcessingDelayで一回ready。途中fragmentではarrival/receptionを生成しない。元frameのterminal対象は送信源からの最初のfragment SOFで固定し、最後の受信処理完了だけでsuccessとする。Switch hopでは新たなframe分母を作らない。express receptionは通常どおり。frame単位の凍結対象と完了は後述delivery schemaで明示する。

既存`ethernet.dynamic.transfer/1`をpreemptableの長い経過spanへ流用すると連続busyを偽る。このprofileは全transfer（express含む）を専用`dir.preemption.transfer/1`へ置換し、dynamic frame/reception/control/policy4種とTSN4種を再利用する。既存transfer schema自体は変更しない。reception.transfer_idとTSN decision.transfer_idの参照先schemaはprofile catalogで`dir.preemption.transfer/1`に固定する。

### 3.5. 共通出力・互換性

新record envelopeは現行`ModelRecord`のJSON projectionと同じexact `schema_name:S,schema_version:J,record_id:S,subject:S,request_id:S?,origin_request_id:S?,time_ps:D,data:object`。time_psは最後の成功upsert時刻。data.effect_seqはcommit順u64十進文字列、同時刻replayはeffect_seq順。subjectはport/stream/Gatewayの所有target、request_idは元frame/request ID、origin_request_idは修飾root ID。新schema.version=1、top-level versionとdata内数値の表記は混同しない。3.2の既存bridge dataと3.4のWireV1内の数値は現行output/network::decimalsによるD化を維持する。referencesは内部で(schema,record_id)の組で保持し、JSONの裸ID fieldのschemaは各profileのmetadata `reference_catalog`（source schema/field/allowed target schemas）で固定する。同じ裸IDが複数allowed schemaに実在して曖昧になる場合は作成preflightで拒否する。synthetic/nativeのnamespaceを区別する。未知schemaはViewer load時に明示非対応とする。

現行bridge exact fieldsはConversion=`conversion_id/origin_id/parent_id/gateway/ingress_record/rule_id/visited_gateways/observed_ps/ready_ps/planned_ready_ps/released_ps/status/reason/branch_ids`、Branch=`branch_id/conversion_id/egress/child_id/planned_child_id/codec_length/pcp/input_format/input_can_id/output_format/output_can_id/offer_ps/planned_offer_ps/admitted_ps/sof_ps/status/reason`、Segment=`segment_id/origin_id/source_record_id/branch_lineage/sof_ps/target_count/targets`。Target exact=`origin_id/segment_id/branch_lineage/terminal_id/completed_ps/completion_reception_id`。nullable・status・codecは既存変換仕様を保持。planned_child_idは計画識別子で実在child参照ではない。新compositeではingress_recordがsyntheticを指すのではなく、conversionは元の実媒体受信を指し、synthetic recordがconversion/branchを参照する。

停止は[0,T)。t=Tのfragment end/express EOF/arrival/gap/wake/control/SOFは発火しない。initial policy/gate/empty decisionは既存同様T=0でもinitialization recordとして保存する。runtime failureは直前成功commit時刻Hと成功prefix、future planを分離し、失敗callbackに一切upsertを残さない。正常limit Tのbusy積分は[0,T)、異常prefixの積分は[0,H)、Hの成功点recordは保持するが幅0。通常runの外側schema2は維持する。P-CONTROLの新しい静止export又はMetric V2を明示選択した場合だけ、横断提案が定める外側schema3 envelopeへ同じcommitted model_recordsを投影する。本書はその機能の自動有効化を行わない。process checkpointは別capabilityで、本書でserializer実装済みを主張しない。将来の採用時もfragment/sequence/history/全epochを含む版付きcodecが無いprofileは明示UnsupportedCapabilityとし、結果JSONから復元しない。

## 4. Architectureの責務

<a id="p-composite-a01"></a>
**P-COMPOSITE-A01**（S01）：input/networkがcomposite wrapperを解釈し、bridge validatorをEthernet再decodeから分離する。ResolvedNetworkを一個だけ作り、bridgeには参照indexを渡す。Registryは一profile factoryと全schema/metricのcatalogを所有する。

<a id="p-composite-a02"></a>
**P-COMPOSITE-A02**（S02）：runtime/network coordinatorだけがFESを予約する。BridgeStateは変換/RX/枝のdecision、TsnStateはgate/credit/tokenを所有する。admission plannerは両差分のstaged viewを見る。BridgeAction::InjectEthernetの前にpolicing verdictを追加し、既存source_offerを再帰呼出しして二重計上しない。

<a id="p-composite-a03"></a>
**P-COMPOSITE-A03**（S03）：NetworkDeltaがBridgeDelta/TsnDelta/queue/typed lineage/recordsを束ね、registered::NetworkArena::prepareとNetworkState::reserveが全effectをpreflight。output/networkがschema2とmetadataを投影、Viewerはdynamic visit＋bridge lineageを純粋replayする。

<a id="p-replication-a01"></a>
**P-REPLICATION-A01**（S01）：ReplicationPrepareはbase TSN prepareの解決済みdirection graphへcircuitを照合し、PreparedReplicationにimmutable path/stream/limitを所有する。既存L2 routing modeとは明示enumで分ける。

<a id="p-replication-a02"></a>
**P-REPLICATION-A02**（S02）：NetworkState内ReplicationStateがsequenceとRecoveryStateを単独所有。CircuitCursorはtyped frame sidecarに置き、wire payloadを変更しない。TsnState/queueは共用。RecoveryPlannerはdeltaを返すだけでFES/Registryに直接触れない。

<a id="p-replication-a03"></a>
**P-REPLICATION-A03**（S03）：ReplicationDeltaをNetworkDeltaへ加え、origin/branch/recovery upsertとterminal-deliverを同batchでcommit。spoolは既存journal、historyだけN bit有界。Viewerは枝送信と原frame成功を別集計として読む。

<a id="p-preemption-a01"></a>
**P-PREEMPTION-A01**（S01）：PreemptionPrepareはbase TSN output/classへ分類を付加し、既存transfer schemaを新schemaへprofile局所で置換。旧catalog/DTOは変更しない。

<a id="p-preemption-a02"></a>
**P-PREEMPTION-A02**（S02）：EgressFragmentStateはNetworkStateのport内に一つ。通常TSN Headのoccupancyを次fragment durationへ差替え、expressのHeadは既存timingを使う。TsnStateは適格性だけ、FragmentSchedulerがexpress優先/continuationを決める。preemptableのCBS状態は生成しない。

<a id="p-preemption-a03"></a>
**P-PREEMPTION-A03**（S03）：FragmentDeltaはqueue dequeue、active/suspended、timer intent、終端arrival、recordを所有する。shared coordinatorがtimerを予約し、preflight後のみcommit。output/networkはfragment区間のunionからbusyを集計し、Viewerは同区間で方向線を描画する。

### 5.2. Compositeアルゴリズム

<a id="p-composite-d01"></a>
**P-COMPOSITE-D01**（A01）：prepare順は①root exact decode、②NED CAN/全二重Ethernet解決、③dynamic config/workload、④TSN wrapper adapter検査、⑤bridge所有/codec/rule照合、⑥synthetic ingress keyとVID/PCP照合、⑦fanout/初期予約上限、⑧canonical化とmetadata凍結。branch同じqueue資源はindex参照で共有し、独立cloneを作らない。CAN sourceとEthernet source generatorの同名を許すがoriginは媒体prefixで分ける。

<a id="p-composite-d02"></a>
**P-COMPOSITE-D02**（A02）：`plan_conversion_offer(committed,delta,branch,now)`はstaged branchからpolicing_evaluated/verdictを読み、未評価なら`TsnState::plan_arrival_in`へsynthetic ID/ingress/M/keyを渡す。pass/bypass/dropをstaged branchへ保存し、次にbridge_txのstaged queue viewでAdmissionを計算する。Waitingはchild未実在、Admittedで初めてchild＋transferを公開し、全枝terminal-admission後だけRXを解放する。PSFPとcapacityの順序を逆転しない（満杯でWaitingになってもpassのtokenは消費済み）。再offerは既存bridge actionを使い、判定済みtokenを再消費しない。

<a id="p-composite-d03"></a>
**P-COMPOSITE-D03**（A03）：`NetworkDelta`の仮record ID/seq、RX差分、meter、queued bytes、wake、segment targetを全て仮計算する。preflightはtyped参照閉包→算術→catalog/schema/target→state/record/FES容量予約の順。commitは確保済み値のmove/swapだけ。2枝目の予約失敗でも1枝目のrecordは残さない。通常dropは差分として成功commitする。

### 5.3. Replicationアルゴリズム

<a id="p-replication-d01"></a>
**P-REPLICATION-D01**（A01）：PreparedReplicationはstream ID順、path ID順に固定。各portをdirection indexへ変換し、連結・終点・device再訪をvisited setで検査。全stream bitmapはprepareで必要word数ceil(N/64)を確保する。source_generator→stream indexは一対一map、未一致generatorはbase経路。

<a id="p-replication-d02"></a>
**P-REPLICATION-D02**（A02）：origin受付batchは`seq=next; branches=K`をreserveし、K個のsidecar `(origin,stream,seq,path_index,hop_index=0)`を作る。path index順offerが同deltaのqueue差分を見る。hop受信時は元frameに戻してfloodせずcursorを次へ進め一件offerする。最終受信処理完了ではhigh/bitmapの必要wordだけdeltaへ複写し3.3表を適用。d>=Nはclear、d<Nはword shift＋mask、残bitを0へ正規化。bitmap更新・decision record・一回deliverのいずれかが失敗すれば全部rollback以前の状態を維持する。

<a id="p-replication-d03"></a>
**P-REPLICATION-D03**（A03）：`OriginState{target_frozen,completed,delivered_branch}`でfirst SOFの分母を一回凍結。原frame別successはこの状態だけを使い、raw branch reception数を流用しない。全branch terminalでもorigin auditはspoolへ残す。historyは全origin終了を待たずstreamごとに進み、遅すぎるoriginがstaleで未達になることを許す。bitmapがwindow外に落ちた後に同originが戻ってもstaleで再deliverしない。pending状態のみメモリ保持、終了recordは既存spoolを利用する。

### 5.4. Preemptionアルゴリズム

<a id="p-preemption-d01"></a>
**P-PREEMPTION-D01**（A01）：PreparedPreemptionはport indexにclass mask/F/O/gapを持つ。F+Oはu64でchecked、8*(L+O)*10^12はu128でchecked。一fragment duration0にならないこと、R>0、静的first fragment/gapの時刻をprepareで検査できる範囲で検査する。将来累積時刻は開始callbackでchecked、EOFがu64を越える開始はcommitしない。

<a id="p-preemption-d02"></a>
**P-PREEMPTION-D02**（A02）：選択候補はexpress集合内の各class先頭、次にsuspended continuation（あればそれ一つ）、無ければpreemptable各class先頭。TsnStateの各class gate/credit/fit結果を使い、eligible express最大priority→continuation→eligible preemptable最大priorityを選ぶ。開始fragmentはM-offsetのminを使いtx_epochを進め、active recordを作り完了tokenを一件予約する。完了時にoffsetを一回進め、remaining0なら最終arrivalを計画し、非0ならSuspended/readyへ。express群のreleaseのphase2でeligible expressが無い時だけgapを作る。gap消費済みflagをcontinuationに持ち、gate待ち/wakeで再作成しない。新express群が開始したらflagを未消費へ戻す。

<a id="p-preemption-d03"></a>
**P-PREEMPTION-D03**（A03）：`FragmentDelta{port_state,queue_remove,fragment_upserts,gap_upserts,arrival_intents,decision,metrics}`をNetworkDeltaへ統合する。開始時は一frame dequeueとcapacity wakeが同batch、完了時はfragment endとoffsetが同batch、最終時は元EOFとarrival intentが同batch。metricsのbusyは[SOF,end)の区間と停止snapshotの交差長だけを加算する。expressは[SOF,release)、fragmentは[start,end)、gapは[start,gap_end)。planned endを実績終端に変換しない。frame recordの経過spanをbusyへ単純加算しない。
