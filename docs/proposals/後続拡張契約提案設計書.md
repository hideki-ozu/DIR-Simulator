## 1. 構成と責務

| 提案ID | 構成/所有者 | 接続する既存境界 |
| --- | --- | --- |
| P-COMPOSITE | CompositeConfig validator、NetworkState内のBridge/TSN partition、NetworkDelta | Registryの一profile選択、private network staged coordinator、schema2結果 |
| P-REPLICATION | ReplicationPlannerとRecoveryState（streamごとのwatermark/bitmap） | 通常Ethernet frame受付/egress、record/effect batch |
| P-PREEMPTION | EgressFragmentState（frame、offset、remaining、kind、epoch） | port占有、通常class選択、frame完了通知 |
| P-WIRE | ProtocolAdapter→ValidatedControlBatch→NetworkDelta | packet到着、既存control epoch/validator。adapterはFESを直接変更しない |
| P-CONTROL | RunSessionがengineを単独所有、ControlMailboxとack台帳 | Engineのcommit境界、snapshot freeze、既存manifest-last writer |
| P-METRIC | FrozenMetricV2とMetricAccumulator | Registry prepare、Context effect preflight、snapshot/output |

独立エンジンをwall-clockで同期する方式は採らず、event時刻・順序・成功prefixを一つにする。既存公開Model traitにclone、rollback、serializeを要求しない。built-in native adapterは段階移行し、未対応adapterで制御APIを指定したらprepareでUnsupportedCapabilityを返す。通常runを拒否する理由にはしない。

## 2. Composite coordinator

<a id="composite"></a>

prepareは①各subconfigを既存validatorで検査、②port/queueの単一所有者を確定、③codec出力のVID/PCP/classとTSN参照を解決、④fanoutと予約上限を検査、⑤profile/schema/metric catalogを凍結する。設定値を複数partitionへ複写して別々に変更可能にしない。

callbackはcommitted stateを読み、同一NetworkDeltaの先行差分を参照して後続判断する。変換frameのPSFP判定→枝のdrop又はqueue admission→RX release→後続wake予約の順にdeltaを構築する。gate閉鎖はこのadmission手順を変えず、phase2の送信適格性だけを変える。全effect/参照/算術/必要容量をpreflightし、成功後のcommitは確保済み所有値の移動だけとする。途中のone-branch失敗を枝dropへ読み替えない。

lineage indexはschema-qualified IDをキーとし、元CAN requestとEthernet frameが同じ文字列でも衝突させない。bridge RX保持数、queue bytes、TSN token/credit、FES pendingと公開recordは同じbatchで進める。exportが見るのは最後の成功状態のみである。

## 3. Recoveryとfragmentの状態

<a id="replication"></a>

RecoveryStateは`Option<u64> high`、容量N、N bit bitmapを持つ。highなしならseqをhighとしてbit0を立てる。新しいseqとの差dがN以上ならbitmapをクリアし、d<Nなら既存bitを古い方向へdだけずらす。古いseqは`high-seq`で添字を計算し、N以上はstale、既知bitはduplicate、それ以外は受理してbitを立てる。減算は比較後に行い、符号付きcastと巡回算術を使わない。state deltaとdeliver effectの同時commitにより、失敗後の再試行で受理bitだけが残ることを防ぐ。

fanoutは経路を正規順に整列してpath indexを固定する。予定branch IDを実在record参照にしない。最初の複製commitで全branchの作成とroot参照を同時に公開し、各枝の進行を独立upsertする。モデルの履歴はNで有界、journalは既存spoolへ退避する。

<a id="preemption"></a>

EgressFragmentStateは元frameと次offsetを保有し、通常queueは最初のfragment開始で一回だけ除去する。fragment完了callbackでremainingを減らし、0なら一回だけframe完了を通知する。remaining>0ならphase2 selectionを予約し、同時刻に到着したexpressを先に可視化する。expressが選ばれた間は元frameをSuspendedに保持し、queueへ戻さない。resume gap中にexpressが到着した場合も、gap終了後に再度express優先で選択する。

古いfragment完了/wake eventはport epoch不一致として無効果化する。portは常に高々一つの実占有区間を持つ。recordはframe ID/fragment ordinal/offset/length/start/end/epochを保持し、end未到達はnullとplanned endに分ける。初期実装はfragmentのpayloadとoverheadの境界を観測するだけで、標準wire byteを捏造しない。

## 4. Wire adapterの実装引継ぎ条件

<a id="wire"></a>

共通parserは最初に長さ上限、hex、versionを検査し、その後にadapterへ不変byte列を渡す。adapterは長さを検査してから各fieldを読む。入力が宣言するcountをそのまま容量予約へ使わず、残byte数と上限の両方で照合する。一PDUの最後まで構文・意味検証が済むまでcontrol deltaを返さない。

`ValidatedControlBatch`はprotocol、revision、port、actions、timer intents、source packet IDを持つ。timer intentsは状態epochと期限を含み、共通plannerだけがFESへ予約する。適合表は受理packet kind/拒否kind/length/checksum/互換版/state遷移/timer/送信packet/出典条項/独立vector hashを一行ずつ持つ。全行の期待byteとtimer/state遷移を固定するまでadapterをRegistryへ公開しない。

現時点でRSTP/MVRPの全状態表とIEEE版は未確定、IGMP/MLDも候補RFCから全対応表を導出していない。この不足はコード実装担当の裁量で埋める項目ではなく、追加設計レビューで解消する。構造checker成功や共通malformed packet試験を標準適合の合格に数えない。

## 5. RunSessionと制御境界

<a id="control"></a>

RunSessionはengine、状態、control queue、ack cache、opaque token generationを所有する。engineを操作するthreadは一つで、他threadは要求enqueueとack取得のみ許す。各callbackの開始前と成功commit直後に要求を取り込む。callback失敗は状態をFailedへ移し、未処理要求へterminal ackを返す。commit完了後のStop/Pauseの優先は仕様どおりとし、同種要求はFIFOで処理する。

Paused/Stopped/Completed/Failedのexportは元の静止状態を保持する。Pausedはengineを破棄せず、次eventをpopしない。exportは凍結snapshotだけを読み、resumeはexport作業中Busyを返してsnapshotの寿命と衝突させない。tokenはsession ID/generation/fingerprintに対応するprocess内handleで、直列化しない。resume成功時にgenerationを消費し、再pauseで新しいtokenを発行する。export結果のrun lineageは共通run IDとexport ordinalで関連付け、再開後も記録の通算seqを保持する。

pendingとackを合わせた予約枠は最大64件とし、enqueue時にack用の枠も予約する。満杯なら新要求をBusyにしIDを消費しない。取得済みackは呼出元の明示forgetで消去し、その後に同じrequest_idを再利用したらDuplicateExpiredとして拒否するため、session内の新request_idは厳密増加u64とする。キャッシュ検索後、受理済み最大ID以下の未保持IDをDuplicateExpiredとするため、期限切れID集合を無限保持しない。u64使い切りは制御APIのResourceExhaustedで、engineの結果を壊さない。制御recordは再現注入用commit ordinalを保存し、通常simulationのevent数やmetric母数には加算しない。

永続checkpointを将来追加する際は、モデルごとのoptional capability、versioned serializer、入力とcode fingerprint、FES payload schema、全spool hash、破損/不一致のfail-closed検査が必要。結果CSV/JSONだけを再開入力とする経路は設計しない。

## 6. V2指標の追加

<a id="metric-v2"></a>

公開v1型は変更せず、Registry内部ではLegacyPointかV2のenumへ正規化する。prepareで合法なsampling/aggregation組合せを検査し、V2 profileのmetric catalogを凍結する。Contextの追加観測methodはtyped u64 point/gaugeだけを受け、metricの種別と一致しなければModelErrorを返す。

Accumulatorは対象ごとにcount/sum/min/max、gaugeのlast time/value/area、現在窓を保持する。EffectBatch preflightで既存Accumulatorとbatchから次状態をchecked計算し、commitでは完成済みdeltaのみを適用する。Hの成功点は全体summaryに入り、異常prefixの半開窓には入らない。出力write失敗をcallback成功の取消しとしない。point/identityだけのv1 profileは従来records/空summaryを維持する。

## 7. 実装順序と完了判定

| 段階 | 変更候補箇所 | 終了条件 |
| --- | --- | --- |
| 採用レビュー | 要件・機能・API・schema docs | 各P-IDの採否、版、未確定項目を決定し、正式traceを別変更で追加 |
| prepare | input/network、Registry catalogs | valid/invalid構成、上限、未知field、旧profile拒否の独立ケース |
| 実行 | runtime/network、registered、run | delta失敗注入、同時刻順、停止境界、再開等価性 |
| 出力 | snapshot、output/network、viewer loader | 新schema参照閉包、未完了表示、計測母数、旧fixture互換 |
| 公開 | examples、CLI help、API docs、検証記録 | fmt/clippy/locked tests、strict trace、viewer実機確認。未実行を合格にしない |

P-WIREはadapterごとの追加設計完了が実装の前提である。他提案を先に採用できる。異なる提案の機能を一profileへ無制限合成せず、組合せごとにprepare/順序/母数の受け入れを追加する。

## 8. 標準adapterの残設計を閉じるための成果物

P-WIREは共通入口設計までの状態である。次の順で追加レビューし、一項目でも未確定なら該当adapterを公開しない。

| 決定 | 作成する具体成果物 | 完了判定 |
| --- | --- | --- |
| revisionと役割 | IGMP/MLDは候補RFCのhost/router/snoopingの採用役割、RSTP/MVRPは取得済みIEEE版・条項一覧。対応外役割も列挙 | 承認者と版・errata確認日を記録し、抽象操作への単純変換だけで標準適合を名乗らない |
| bytes | field offset/width/endian、最小最大長、count検査、checksum対象、未知type処理、生成byte列の表 | 正常・切詰め・count不一致を独立byte vectorと照合 |
| state | 状態×受信種別×guard→次状態/action/timer取消・予約の全行。未該当は明示no-op/drop | 各行にケースIDを割当て、二つのrecordを含むPDUの原子性も検証 |
| timers | 単位、既定値の条項、許容範囲、丸め、同時刻順、epoch失効、再送上限 | deadline-1/deadline/deadline+1の独立期待遷移を保存 |
| resourcesと出力 | group/source/port/timer上限、生成packetの媒体占有、状態から公開recordへの写像 | 上限と上限+1、packet drop時のstate不変、参照閉包の期待値を固定 |

これらは追加設計への引継ぎ条件であり、未作成の状態表を作成済みに変更するものではない。IEEE版・資料が未確定のため、本改訂では規格由来のbyte値・timer値を設定しない。
