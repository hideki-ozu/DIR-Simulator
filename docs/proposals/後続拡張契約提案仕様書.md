<a id="composite"></a>
Gateway＋TSNは変換設定にEthernetを重複所有させず、トップの一instanceへ接続する。PSFPはoffer時一回、Waiting後の再offerで再消費しない。gate待ちと容量待ちを分ける。

<a id="replication"></a>
冗長配送はDIR独自抽象であり、IEEE 802.1CB適合ではない。非巡回u64 sequence、有限bitmap、静的なsource-routed circuitを採用する。

<a id="preemption"></a>
分割送信もDIR独自抽象である。IEEE MAC Merge／SMD符号化／verify handshakeを実装した扱いにはしない。算術kernelの短いexpress例と合法Ethernet frameのwire時間例を区別する。

<a id="p-core-s01"></a>
## 2. P-CORE-S01 選択・互換性・入力

P-CORE-F01を具体化する。候補profileは一つを明示選択し、暗黙の配列合成を拒否する。モデル設定とworkloadは各専用schemaで判別し、未知/重複key、未知版、必須欠損、不適切なnull、型違い、範囲外をprepareで位置付き診断にする。u64 psは`0|[1-9][0-9]*`の十進文字列、boolは整数ではない。省略値は各表に記した値だけを用いる。既存profile・Model/Channel必須trait・V1指標は保持し、新APIは追加又は既定Unsupportedのoptional capabilityとする。

<a id="wire"></a>
### 2.1 共通wireのexact rootとadapter union

model-configは次の**5 fieldのみ**を必須とする。全配列は入力順をpacket時刻順へ読み替えず、予約順は分野の安定キーで決める。

```text
{schema_name:"dir.ethernet_control_wire.config",schema_version:1,
 ethernet:DynamicEthernetConfigV4,port_identities:PortIdentity[],adapters:WireAdapterConfig[]}
```

`ethernet`は既存schema4の`schema_version/endpoints/switches/ports/outputs/dynamic`構造を継承する。同runにwire RSTPが一つでもあれば、共通の必須scalar `ethernet.dynamic.convergence_ps`を`"0"`固定で受理する。wire ownerでは未使用、併存するabstract領域もその0を使う。wire RSTPがないrunだけ従来値を許す。RSTP adapter内の`convergence_ps`は未知fieldとして拒否する。INIのprofile/model-config/workload指定は既存の明示指定方式を継承する。`port_identities`は必須配列で、各要素は`{port,source_mac}`だけを持つ。portは既存switch output ID、source_macは小文字colon表記のunicast MAC（全0不可）。active RSTP/MVRP portsのunionを過不足なく列挙し、port重複と送信MAC重複を拒否する。IGMP/MLDだけの構成では空配列。制御TXのSAはここだけを参照し、RSTP bridge ID用addressとは役割を分ける。

`adapters`は非空。同protocol/bridgeは一instance、各instanceのportsは一bridge内とし、異なるbridgeで同protocolを複数設定できる。RSTP instanceは当該bridgeの全接続portを所有する。idは非空ASCII `[A-Za-z0-9_.:/@-]+`で一意。各adapterは共通必須`id/protocol/protocol_revision/ports`と、次表のprotocol別fieldだけを平坦に持つ。`options`、最上位`limits`、最上位`packet`は存在しない。各protocolの上限・timerはadapter内に一度だけ置く。

| protocol判別 | 追加field／省略・既定値 | ports／revisionの定義 |
| --- | --- | --- |
| `igmp`／`mld` | `role/max_pdu_bytes/max_sources_per_record/max_groups`必須。`max_filter_leases/max_sources_total/membership_interval_ps/router_interval_ps`はmembership表のdefaultのみ | switch ingress port。prepared topologyの対向output portを一意に解決。revisionは`igmp-rfc9776-2025`／`mld-rfc9777-2025` |
| `rstp` | `max_pdu_bytes/max_state_entries/max_pending_timers/max_pending_tx/max_control_steps/rstp`必須。rstp objectは[RSTP規範補足](implementation/RSTP規範仕様・詳細設計書.md)の全field/defaultを正とする | 一bridge内の全output port。revision=`ieee802.1q-2022.rstp.initial.v1` |
| `mvrp` | 共通上限`max_pdu_bytes/max_state_entries/max_pending_timers/max_pending_tx/max_control_steps`と`max_attributes_per_pdu`必須。`port_parameters/registrar_controls/local_declarations/random_seed`は[MVRP規範補足](implementation/MVRP規範仕様・詳細設計書.md)のfield/default。adapter内registrableは拒否 | 一bridge内のoutput port。revision=`ieee802.1q-2022.mvrp.initial.v1` |

標準設定は各規範補足に固定済みで、この表は現行限定実装が採用したschema契約である。validator/runtime/profile登録へ接続した。IGMP/MLD/RSTP/MVRPは異なるfamily stateとして同一portで併用でき、所有状態が重なるabstract更新だけを拒否する。MVRPを配置する物理連結領域は全bridgeにMVRP instanceを一つずつ必須とし、各instanceはそのbridgeの全接続portを所有する。未対応bridgeを挟む構成と部分port配置をprepare拒否する。これは非対応bridgeのMVRP relay（IEEE §10.8.3.2(b)）を初期scope外とするDIR制限であり、標準がdropを要求するという意味ではない。wireとTSN／Gateway／冗長配送／preemptionとの合成も拒否する。

workloadは次の**4 fieldのみ必須**。`ethernet`は既存dynamic workload4を所有する。`packets`は空可、defaultはなく必須である。

```text
{schema_name:"dir.ethernet_control_wire.workload",schema_version:1,
 ethernet:{schema_version:4,generators:[],controls:[]},packets:WirePacket[]}
```

WirePacketは共通必須`id/adapter_id/ingress_port/arrival_ps/encapsulation/bytes_hex`を持つ。idは非空UTF-8・run内一意（generator/controlとはschema-qualified namespace）、adapter_idは存在するadapter.id、revisionはそのadapterから一意に取得しpacketへの重複`protocol_revision`は拒否する。arrivalは受信完了時刻、T以後も構造検査する。`ingress_port`はadapterの対象port又はその一意対向ingressに一致させる。

| encapsulation | 有効protocol | 追加必須field／byte境界・時間 |
| --- | --- | --- |
| `ip_packet` | igmp/mld | `vid/source_mac/destination_mac`。IP headerから末尾、L2/FCSなし。明示MACからserializerがframeを作り、Start／Arrival／ReleaseでRX占有も計測。型・上限・重複検査はmembership §3.1 |
| `mac_frame_fcs` | rstp/mvrp | 追加fieldなし。DAからFCSまでの完全MAC frame。external_injection境界でpeerの到着以前を計測しない。内部adapter TXは実媒体を占有。bridge §3.3 |

判別とprotocol不一致、余計なfield、未登録adapterはprepare拒否。checksumや内部count等の不正は到着時control_dropで、全PDUを検査後一括適用する。これらの二種類は入力境界が異なるため、RX実績の有無をmetadataのencapsulationで明示する。同じ物理linkへの境界刺激と通常source workloadの併用を拒否する。wire内部転送copyには元packet.idと送信元adapter_idをlineageとして保持する。内部PDUの受信ownerはpeer ingressのprotocol/bridgeから解決し、送信元adapter_idへ渡さない。RSTPの未設定受信owner又は未対応endpointへの制御packetは消費・dropする。MVRPのowner不在bridgeは上記領域検査でprepare拒否するため、run中のMVRP受信で到達させない。内部不変条件違反で到達した場合はrun失敗とし、標準上の通常dropへ読み替えない。各受信eventは自分のadapter_idと設定revisionを記録する。

通常multicast **データ**は既存の`ip_multicast` metadata（family/source/group）を転送判定に使い、data bytesは不透明のままにする。wire-authoritativeなIP checksum／group判定はこの版では**制御packetだけ**である。通常dataのfull-IP parser、fragment/reassemblyや不一致dropを追加した扱いにしない。null metadataは既存L2転送、非nullなら既存のEtherType／MAC対応検査を維持する。

<a id="p-core-s02"></a>
## 3. P-CORE-S02 成功境界と資源

P-CORE-F02を具体化する。FESは既存の`(time_ps,delta,phase,seq)`、実行は半開[0,T)。同時刻の制御・期限・完了はphase0、到着phase1、選択phase2。callback全体で状態／FES／queue／ID／record／計測をpreflightし、予約完了後に同一Deltaをcommitする。新しいframeが実送信を始める前に予定EOFを実績へ入れない。

RunSessionの要求はownerがpollする境界で直列化する。失敗→Stop→Pause→自然終了の優先、初期化中の非割込、境界snapshot単位のreplay、token・cleanup・ackの規則は実行基盤設計を正とする。任意Model内部にrollbackを強制する意味ではない。失敗後はlive stateを再開せず、成功journal prefixだけをexportする。

<a id="control"></a>
停止結果snapshotと永続checkpointを分離する。同一process tokenの保存は永続化ではない。初期checkpointは全モデル／channelのoptional codecが揃うgeneric登録backendだけを対象とする。network backendは協調制御対応を先に行い、checkpoint codec対応まではUnsupportedCapabilityを返す。

<a id="p-core-s03"></a>
## 4. P-CORE-S03 出力・母数・設計証拠

P-CORE-F03を具体化する。現行通常runのschema1/2を保持し、協調制御の明示export又はMetricV2ではschema3を選択する。network新profileの通常結果はschema2の専用recordで識別する。checkpoint manifestは結果schemaとは別版である。新schema/recordのViewer loader、planned/actual、origin/branch/fragment、null・空集合の扱いを分野設計の表へ割り当てる。

<a id="metric-v2"></a>
MetricV2の初期集計は整数pointのidentity/sum/count/min/max/meanと整数gaugeのtime_mean。u128でchecked累積し、最後に一回だけbinary64へ丸める。停止時刻Hの点はglobal summaryへ入り半開窓から除外し、H時刻bucketを次の成功時刻まで保持する。freeze/exportはlive積分器を進めない。

六工程のP-IDは提案内traceであり、正式DIR要件や製品合格へ自動変換しない。一次資料と独立期待値の検査、製品実行、規格適合を別々に記録する。IEEE原文の採用範囲・解釈・独立レビューを規範補足と検証記録に保存する。
