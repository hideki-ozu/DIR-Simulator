## 1. P-COMPOSITE: GatewayとTSNの合成

<a id="composite"></a>

候補profileを`can.ethernet.tsn.v1`、model-configの候補schemaを`dir.can_ethernet_tsn.config` version 1とする。最上位は`schema_name/schema_version/bridge/ethernet/tsn/limits`のみを受理し、bridge・ethernet・tsnは各既存schemaの内容を名前空間付きで保持する。既存profile名の配列や暗黙の機能検出で合成しない。単一Registry/prepare/FES/終了境界を使用する。

| 項目 | 提案する契約 |
| --- | --- |
| 入力照合 | 所有port、VID、PCP→traffic class、stream IDを全体で照合する。各portのqueue容量はethernet側だけを正本とし、bridge側の同じ資源の容量再定義は準備失敗。CAN FD/半二重との混在は初版では準備失敗 |
| 分類 | CAN→Ethernetのcodec/VID/PCPを変換readyで確定し、生成Ethernet frameを通常のTSN ingressへ一回投入。PSFPで拒否なら変換枝を終端dropとし、Ethernet queueへは入れない |
| 時間順 | 同時刻は既存FESのphase順を保持。制御更新と解放をphase0、到着・readyをphase1、egress選択をphase2とする。同phaseは既存の決定的連番順。同じ時刻のgate更新はその時刻の選択より先に適用する |
| 入場と送信 | TAS閉鎖/CBS不足はqueue入場拒否ではない。容量があればAdmittedとしてbridge RX保持を解除可能にする。容量満杯だけWaiting、PSFP拒否/過大frame/容量0はDropped。SOFでqueue容量を解放して全classの待機枝を既存ready順で再評価する |
| 出力母数 | conversion/branch/segmentのlineageを維持し、TSN待機を新しいoriginや送信成功に数えない。terminal母数は実SOF時に固定。PSFP dropは一枝一回、受信未完了は未完了のまま保持 |
| 上限 | `limits.max_pending_branches`と`limits.max_control_events`は正のu32で必須。prepareで静的最大fanoutが上限超過なら拒否、動的資源確保不能は成功prefixを保存する実行診断。u64時刻/checked u128算術を共用 |
| 失敗 | 一callbackの変換、PSFP、queue差分、metric、FES予約のいずれかが失敗すれば全batchを棄却。通常dropと内部実行エラーを区別する |

初期状態は空queue、既存TSN設定によるcredit/token、各gateのt=0状態とする。live更新はEthernet/TSNで既に許すものだけを使い、bridge codecとrouteはprepareで凍結する。停止時にgate待ち枝を送信済へ補完しない。

## 2. P-REPLICATION: 冗長配送の抽象profile

<a id="replication"></a>

候補`ethernet.redundancy.abstract.v1`は`ethernet.tsn.v1`の契約に、明示streamの複製と有限履歴による重複除去を加える案である。IEEE 802.1CBのFRERという機能分野は[IEEE公式プロジェクト](https://1.ieee802.org/tsn/802-1cb/)に対応するが、以下のアルゴリズムはDIR独自抽象であり同規格のsequence recovery適合を主張しない。

| 入力 | 境界と意味 |
| --- | --- |
| `stream_id`, `replicate_at`, `egress_paths` | streamは一意、複製点は一つ、経路は2〜16本。各経路は静的で閉路なし。物理的経路独立性は要求せず、共有linkを許した場合も構成に明示 |
| `eliminate_at`, `history_capacity` | 除去点は一つ、容量は1〜65536。起動時の履歴は空。初版は単一送信源のみ |
| `sequence` | origin受付順のu64単調連番。初期0、再利用なし、最大値の次は実行診断。wire上の有限bit巡回を模擬しない |
| `reset` | 実行中の履歴resetは受理しない。新runだけが新しいsequence空間を作る |

除去点は`high_watermark`と幅Nの受理bitmapを保持する。初回seqを受理し、既知bitならduplicate、`seq < high_watermark`かつ差がN以上ならstaleとして破棄する。より新しいseqは窓を進めて受理し、窓内未受理の遅着は一回受理する。同時刻はFES順で最初の一枝だけをdeliverする。sequenceの穴を埋めるために待たない。分岐IDはorigin/path indexを含み、成功はterminalへ届けた原frame単位、複製送信量は枝単位で集計する。最後の枝がdropしても未送信枝を成功へ変えない。

結果に`dir.redundancy.branch` version 1（origin/stream/sequence/path/status）と`dir.redundancy.recovery` version 1（input branch/decision/previous watermark/new watermark）を提案する。抽象sequenceを実wire byte数へ加算しない。wire tagを追加する別profileは別途符号化契約を要する。

## 3. P-PREEMPTION: 分割送信の抽象profile

<a id="preemption"></a>

候補`ethernet.preemption.abstract.v1`では全二重portごとにexpress class集合、preemptable class集合、`fragment_payload_bytes`（正u32）、`fragment_overhead_bytes`（u32）、`resume_gap_ps`（u64）を必須指定する。両class集合は重複せず全classを覆う。パラメータの既定値を規格値と呼ばない。IEEE 802.1Qbuの対象分野は[公式プロジェクト](https://www.ieee802.org/1/pages/802.1bu.html)で確認できるが、本提案はMAC Merge/wire符号化/検証handshakeの実装案ではない。

状態はIdle/PreemptableFragment/Express/Suspended。express到着は進行中fragmentを中断せず、次のfragment境界で選択する。express同士は非割込み、複数expressは既存class優先度/FIFO。expressがなければ次fragmentを直ちに開始し、express処理後の再開にだけresume_gapを入れる。frame末尾は残byte数の短いfragmentを許す。gate判定とCBS更新はfragmentの実占有に適用し、express選択時も通常の適格性を検査する。選択時に一fragmentがgate閉鎖までに収まらなければ開始を待つ。初版でCBSとpreemptableを同classに指定する設定は準備失敗とし、creditの中断中計算法を暗黙に追加しない。

fragmentの所要psは`ceil(8*(payload+overhead)*10^12/bitrate)`。各fragmentの送信時間、expressの送信時間、resume gapを分けて記録する。queueから取り出すのは最初のfragment開始の一回、受信完了は最後のfragment完了＋既存伝搬/受信処理の一回。停止時の未完成frameはin_flightで、fragment完了をframe成功へ数えない。媒体同時占有を禁止し、checked算術の上限超過は実行診断。初版はP-REPLICATION/P-COMPOSITEとの自動合成を許可しない。

## 4. P-WIRE: 標準wire制御の候補と入口契約

<a id="wire"></a>

標準wire候補はIGMPv3、MLDv2、RSTP BPDU、MVRP PDUを個別adapterとして管理する。現行の抽象membership/tree/registration操作を標準packet実装と呼ばない。公開候補名は`ethernet.control.wire.experimental.v1`とし、prepareで有効adapterと正確なrevisionを列挙する。revisionが未実装又は適合vector未承認なら起動を拒否する。

| 候補 | 入口・内部操作 | 採用前に必要な具体化 |
| --- | --- | --- |
| IGMPv3 | IPv4 packet→group/source report/query→membership epoch | [RFC 9776](https://www.rfc-editor.org/info/rfc9776/)と適用errataを基準候補とし、旧版互換を含む採否、timerとquery生成の適合表を作る |
| MLDv2 | IPv6 packet→listener report/query→membership epoch | [RFC 9777](https://www.rfc-editor.org/info/rfc9777/)と適用errataを基準候補とし、IPv6 validation/checksum、旧版互換の適合表を作る |
| RSTP | L2 BPDU→port/tree state遷移 | 採用IEEE 802.1Q版・条項・timer・role遷移・topology changeの対応を合法的に取得した一次資料で確定する |
| MVRP | L2 PDU→VID登録状態遷移 | 採用IEEE 802.1Q版・条項・attribute符号化・registrar/applicant状態機械の対応を同様に確定する |

2026-10-14にRFC EditorでRFC 3376は9776、3810は9777による置換を確認した。候補を後継版に更新するが、ここで候補RFC番号は将来の最新版の保証ではない。実装着手時に後継版・errataを確認し、採用版を固定する。外部資料未照合のbyte layoutや標準timer値を創作しない。このため本節の共通入口・失敗・所有権契約はレビュー可能だが、各標準adapterの符号化と全状態表は未設計として残す。

入力`packet`は`ingress_port/arrival_ps/protocol_revision/bytes_hex`、上限`max_pdu_bytes`（正u32）と`max_sources_per_record`（正u32）、`max_groups`（正u32）を必須とする。hex不正/未登録revision/静的上限超過は準備失敗。動的受信packetの切詰め・長さ不一致・checksum不正・未知必須種別は通常のcontrol_dropとして記録し、状態を一切更新しない。一PDU内の全recordを検証してから一括commitする。adapterはPacket→ValidatedControlBatchだけを返し、Registry/FES/queueを直接変更しない。

制御packetのwire占有と帯域を明示的に計上する。抽象workload操作と同じ状態を二重に更新しないため、一runの同じprotocol/portでwire操作と抽象操作の混在をprepareで拒否する。timerはepoch付きFES eventとし、古いepochは状態変更なしの失効として記録する。未知packetの透過転送可否、互換版の降格、再送/querier選出はadapterごとの承認済み適合表が必要である。

## 5. P-CONTROL: 協調停止・export・再開

<a id="control"></a>

候補APIは`run_with_control(prepared, controller)`、戻りはCompleted/Paused/Stopped/Failedの判別型（Pausedは再開可能なsessionを保持）。停止要求はcallback処理の途中を切らず、次の成功commit境界で取り込む。現行の同期runとNED-editorのprocess停止を同APIの実装済み証拠として扱わない。

| 操作 | 規則 |
| --- | --- |
| Pause(request_id) | RunningからPausingへ進み、処理中callbackが成功すれば確定してPausedになる。commit途中は観測不可。初回イベント前ならH=0、同時刻の残りeventはpendingのまま |
| Export(request_id, destination) | Paused/Stopped/Completed/Failedの静止状態で受理（Failedは成功prefix）。immutable snapshotから既存manifest-last公開。export失敗は元の静止状態を維持し、再試行可能。再開tokenの状態を消費しない |
| Resume(token) | 同一process内のPaused engineだけをRunningへ移す。入力hash/profile/schema/registry fingerprintを照合し、不一致・二重使用・別engineは拒否。resumeはvirtual timeとevent連番を維持 |
| Stop(request_id) | 次のcommit境界でStoppedへ終端化し、未完了を保持した結果をexport可能にする。Stoppedからresume不可。Pauseと区別する |
| 自然終了/失敗競合 | callbackの失敗が最優先でFailedと成功prefixを保持。成功後にStop、Pauseの順で要求を処理し、その後に自然終了を判定。要求なしの同一入力は既存runと一致 |

controllerは最大64件のFIFOで、ack保持中の同request_id・同payloadは同ackを返す。異なるpayloadの同IDはRequestConflict、forget済みIDはDuplicateExpiredとする。満杯は制御APIのBusyで、simulation診断やevent消費を発生させない。ackは単調control sequence、確定event数、virtual time、状態を含む。wall-clockで届く要求の時刻は再現条件ではないため、replay時は記録したcommit ordinalへ注入する。応答時間は「callback一回＋境界処理」でありwall-time上限を保証しない。

Pause/Stopのexportは制御状態を終了理由として別記し、エラーとは扱わない。集計のHは最後の成功commit時刻とし、H点をrecords/summaryへ残し半開窓から除くprefix規則を適用する。Pause/Stopのためにモデルfinish callbackを実行しない。再開後は保持した積分器をそのまま進め、export時のfreezeは積分器を破壊的に延長しない。

公開結果snapshotと再開用checkpointは別物である。初版は同一processのopaque tokenのみで、結果JSONから状態を復元しない。process越しの再開は全モデルの状態serializer、FES envelope、連番、乱数、積分器、spool offsetを版付きで保存する契約が必要な別案として未提供とする。既存Model traitへ必須serialize関数を足さない。

## 6. P-METRIC: 選択可能な集計API

<a id="metric-v2"></a>

現行の`MetricDescriptor{name,unit}`とu64点観測を保持し、追加案`MetricDescriptorV2`と`register_metric_v2`を用意する。V2はname/unit/version/value_kind/sampling/aggregationを持つ。name/unitは現行登録規則、versionは正u32でmetadataでは既存契約どおり十進文字列へ変換する。gauge初期値は各登録targetに一つ必須とし重複・欠落をprepareで拒否する。初版V2ではinteger pointのidentity/sum/count/min/max/mean、integer gaugeのtime_meanだけを受理し、任意式と浮動入力は拒否する。同名v1/v2登録は準備失敗。V2のtarget集合はprepareで凍結し、未観測targetにも空集合summaryを出す。未登録targetはModelErrorとする。metadataのversionは明示指定し、v2意味を選ぶprofileの出力schema改訂を必須とする。

pointは成功commit内の各observe呼出しを一標本とし、同一event内の複数呼出しもeffect順で保持する。aggregationは一記述につき一種だけで、identityはrecordsのみ、その他はrecordsと選択したsummary値を出す。gaugeは初期値必須で右連続保持。同時刻のgauge変更は積分幅0で最後の成功値を以後の区間へ保持する。gaugeとmaxの組合せは初版V2では拒否する。平均の分母0はnull、sum/countの空集合は0、min/maxの空集合はnull。checked u128で和・積分を保持し、出力時にだけ既存の正確比率変換を使う。負値やu64超過は観測APIで拒否し、batch全体を棄却する。窓は既存半開区間と異常prefixのH点除外規則を使う。明示capacityと比率式の組合せは初版V2の対象外とする。

## 7. 採否を要する境界

P-COMPOSITE/P-REPLICATION/P-PREEMPTION/P-CONTROL/P-METRICは、上記の限定された抽象契約で実装へ渡せる提案である。正式採用時は要件・機能・trace経路・profile版・CLI/API仕様を同時追加する。P-WIREは入口契約だけを具体化済みで、adapter別の標準適合表と符号化・timer・状態機械は残作業。標準の全wire実装やprocess越しcheckpointを承認済み範囲と解釈しない。

## 8. 入力・制御境界の補則

提案schemaの未知field、未対応version、重複IDはprepare失敗とする。実行中に増えるstream状態/制御timerとprepareで固定するV2 target数はそれぞれprepareで正u32上限を凍結し、上限超過は成功prefix付き診断とする。ゼロ長preemptable frame、bitrate=0、同一経路の重複指定はprepareで拒否する。preemptionのresume gapはexpressの連続処理群が終了した後に一回開始し、gap中に新expressが到着した場合はgap終了でexpressを選択、その群の終了後に新gapを開始する。gate待ちだけではgapを繰り返さない。

制御APIはRunning開始前にも境界を設ける。そこで受理したPause/Stopは最初のcallbackを開始せずH=0で確定する。PausedでPauseは状態を維持、Stopはtokenを無効化しStoppedへ遷移する。静止終端状態でPause/ResumeはInvalidState、Stopは終端状態を維持してackを返す。RunningでExportはInvalidState。Export中のResume/StopはBusyとし後で明示再要求する。要求の採用境界はmailboxを一回snapshotした時点とし、その後の到着は次境界へ送る。snapshot内のStopをPauseより先に評価し、優先度を除く同種順序はFIFOとする。
