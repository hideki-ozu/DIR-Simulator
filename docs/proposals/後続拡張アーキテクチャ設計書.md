## 構成と所有

| component | 所有するもの | 変更してはいけない他者の状態 |
| --- | --- | --- |
| Registry／Preparation | immutable descriptor、対応能力、schema、解決済み所有表、上限 | 実行中モデル、packetの途中解析状態 |
| RunSession／Engine | FES、dirty、次ID、callbackの順序、成功commit数、停止理由 | codecの意味・通信classの選択規則 |
| NetworkState／NetworkDelta | bridge・TSN・冗長配送・fragment・wire controlの分野状態と同一batchの差分 | Context外からのFES書換え、独立したwall-clock同期 |
| WireAdapter | 不変packetの検証とProtocolDelta、protocol timer intent、送信packet intent | Registry、実queue、FESへの直接更新 |
| MetricAccumulatorV2 | 凍結targetごとの整数値・和・時間積分・窓境界 | モデルの事後問い合わせ、未成功batchの値 |
| FrozenJournal／Exporter | 成功prefixの読取view、出典、保存manifest | live engineの積分器・次イベント |
| CheckpointCodec／Store | 対応能力が明示された全可変状態、版付きbundle、完全性manifest | 結果JSONからの状態推測、別版への暗黙変換 |

すべての可変実行状態は一つのowner threadから操作する。controllerは要求とackだけを共有し、モデルへの可変参照を渡さない。新しいcrate分割や外部シミュレータへの委譲は必須にしない。既存`runtime/registered.rs`／`runtime/network.rs`等の責務を分割して段階的に接続する。

<a id="p-core-a01"></a>

### P-CORE-A01 選択・版・準備責務

P-CORE-S01をRegistryとPreparationへ割り当てる。局所validatorの後に全体のport／queue／VID／stream／codec／metric所有関係を一度だけ解決する。複合profileでも同一queue容量を二箇所へ複写して管理しない。

制御・checkpointはprofile名だけで推測せず、immutableな能力表で照合する。candidate登録を実装していない間は現行のbuiltin登録表を変更しない。初期の対応能力と未対応時の診断は実行基盤分野に明記する。

<a id="p-core-a02"></a>

### P-CORE-A02 イベントとcommitの責務

P-CORE-S02をEngineと各分野のDeltaへ割り当てる。制御更新・期限・完了がphase0、到着がphase1、選択がphase2という既存順序を維持する。同phaseの追加順は各分野の安定キーで先に決める。callbackに渡す不変参照と、そのcallbackが作った先行差分を使って後続判断を行う。

事前検証では予約・cancel・容量・record・metricの差分をすべて検査する。公開時は検査済み値を移動し、片側だけを成功させない。モデル内部を任意にrollbackする仕組みには依存しない。失敗後の出力はjournal、再開に使う状態は成功境界で静止したengineを正とする。

<a id="p-core-a03"></a>

### P-CORE-A03 観測・証拠・引継ぎ責務

P-CORE-S03をrecord catalog、Exporter、設計checker、製品検証へ割り当てる。識別子はschemaで名前空間化し、数値カウンタと母数を分離する。制御通信のwire占有は通常通信と同じ媒体・queueモデルで評価し、packet解析のためだけの無時間経路を暗黙に追加しない。

設計checkerの出力は`design_vectors_not_product_tests`とし、未実装profileの実行合格に変換しない。一次資料不足はadapterの準備状態だけをfalseにし、独立した完成分野まで未設計へ戻さない。製品採用時は既存DIR要件への割当と全工程の承認済み経路を別変更で追加する。

## 分野間の結合を固定する

| 結合 | 採用する境界 | 初期の制限 |
| --- | --- | --- |
| Gateway＋TSN | 変換ready→synthetic ingress／PSFP→queue admission→送信選択 | 一FES、一つのqueue所有者。分野設計が決めた時点で一回だけmeterを消費 |
| 冗長配送＋経路 | 静的な経路別copy→除去点→terminal | 動的treeによって冗長経路を暗黙に一本へ変更しない |
| preemption＋TAS | fragmentの占有区間と選択境界 | 完全frameの連続占有recordへ偽装しない。初期のCBS制約は分野仕様で固定 |
| wire＋抽象制御 | port/protocolごとに一方式をprepareで選ぶ | 同じmembership／tree／registrationへ二重適用しない |
| 制御＋Metric V2 | 成功境界でfreezeしたviewを非破壊export | Pause点Hと半開窓の端点を分け、再開後の積分を継続 |
| checkpoint＋全分野 | 対応codecを持つ静止sessionだけ保存 | 同一process tokenと結果snapshotは永続checkpointの代用品ではない |

## 実装の進め方

最初にRegistryの能力表・input validator・独立vectorを追加し、状態／Deltaとpreflightを接続する。その後に出力・CLI/API・Viewer・配布例と回帰検証を接続する。RunSessionは既存borrowed Engineを自己参照構造へ変換せず、owned prepared参照と実行stateを分ける。具体の所有型とcleanup契約は分野設計を参照する。
