## 独立レビューで解消した項目

| 対象 | 指摘と解消 |
| --- | --- |
| Gateway＋TSN | bridgeとtop-level Ethernetの二重所有を排除。PSFPをoffer時一回に固定 |
| 冗長配送／preemption | 動的treeと冗長経路の矛盾を静的circuitで排除。kernel算術例と合法frameのwire例を分離 |
| membership | 不正L3でもMACからwire時間を計上。Start/Arrival/Release、半開境界とplanned/actualを定義 |
| membership | 同一期限はbridge単位atomic drain、epoch一回。sourceはIP byte順で統一 |
| 共通wire | config/workload exact root、protocol/encapsulation union、packet IDとrevisionの単一所有を統合 |
| 既存data互換 | 制御packetだけwire-authoritative、通常dataはip_multicast metadata＋opaque payloadを維持 |
| 静的VLAN | static member又はregistrableを受理。registrableだけを要求する誤記を修正 |
| MetricV2 | H時刻のmin/maxを後から除去せず有界bucketに保留。後の成功commitでflush |
| 制御 | replayはcommit ordinalとboundary_seqのsnapshot groupingを保存。Channel cleanup ledgerも保存 |
| checkpoint | manifest自己hashを排除。ReadyPauseはcodec catalogのみ・factory0。pending drain gateを明記 |
| checkpoint | publicationとdurabilityを分離。rename後sync失敗は公開済receiptを保持。保存要求を共通ID/ack/retryへ接続 |
| TimerToken復元 | owner/id/live-retired参照をcodec helperで保存・検査。通常APIにtoken constructorを追加しない |
| RSTP情報比較 | 同sender再受信も本文上Superior条件を優先。Repeatedを勝手な非等値guardで到達させず、収束scenarioを追加 |
| RSTP互換受信 | Configの版を問わないrcvdSTPと、TCN version0/1条件を分離。role0は規範本文のRST分類を維持し、参考NOTEで上書きしない |
| MVRP LeaveAll | rLAとtxLAをcoalesceしない。sLA→全local rLA→Registrar txLA→Applicant txLA/txLAFを固定。AA/IN、容量不足、共有媒体、timer再開始を個別期待へ修正 |
| 共通SVRE | bridge/VID entryとport別modeを分離。Restrictedは他portから作られたentryも参照。S外Fixedは初期scopeで拒否 |
| 既存MAC学習 | 現行dynamic学習・agingを維持。Learning中の学習とrelay禁止を分離。RSTPは非edge Fixed mask、MVRP Newはport/VIDだけで動的FDBを削除 |
| FDB原子性 | static entry、別port/VIDを保持。取消し後もgenerationを保存し、再学習後の旧expiryが新entryを消さない。空flushにも完了監査 |
| 共通convergence設定 | 既存schema4の必須scalarはwire RSTPが同runに一つでもあれば0固定。併存abstractも0、adapter内の同名fieldは拒否 |
| MVRP領域 | 未対応bridgeでのdropを標準仕様と誤記しない。初期scopeは対象物理領域の全bridge・全接続port配置をprepare必須とし、混在を拒否 |
| protocol因果順 | newTcDetected→MRP通知、role変化のRegistrar Flush/LeaveAll、Forwarding集合、MAP、New FDB flushを順序化。送信元adapterではなくpeer ingress所有者へ配送 |

最終レビューでは、この設計限定scopeについて未解決P1/P2指摘はなかった。ソースhash・レビュー範囲・検査要約は[検証来歴JSON](design-review-2026-10-17.json)に保存した。

## 残る製品検証と採用範囲

RSTPは単一CIST・全二重point-to-point、ForceProtocolVersion=2に固定し、10機械／64状態と旧STP互換を設計した。166 vectorsは64 state entryと45 one-guard遷移を含む。MVRPはFull Participant・context0・領域内全bridgeを対象に981 vectorsを作成し、Applicant/Registrar/LeaveAll/Periodicの刺激軸を列挙した。別に統合18件と旧DIR境界20件を持つ。これらは設計期待値であり、全guard組合せを実行した製品の適合vectorではない。

IEEEの採用版は2022 base edition。独立レビューで本文と参考NOTEの優先、DIRの決定順序、乱数・丸め、現行S/Aへの対応を明示した。後続amendmentや改訂draft、全MSTI/provider/shared-LAN対応を暗黙採用しない。

実装採用時は分野別製品vector実行、全guard組合せ、複数bridge収束／撤回、旧profile/API回帰、実I/O故障、CLI/API・Viewer確認が必要。現記録をその製品合格として使わない。
